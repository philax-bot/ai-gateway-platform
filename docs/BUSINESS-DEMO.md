# 商务与解决方案内部演示

目的：用 15–20 分钟讲清企业如何开放 AI 能力、按人员／项目／应用控制使用，并从费用看板追溯到具体调用和处理结果。

本轮已完成原工作区完整彩排，结果与截图见 [2026-11-02 演示验收](validation/business-demo-2026-11-02.md)。

## 入口与准备

日常启动仍使用仓库根目录的 `pnpm dev`，入口为 [信标界面](http://localhost:5176/?ui=beacon)。原 PostgreSQL 工作区、数据和外部模型 opt-in 配置保留。

本轮已为原工作区添加专用演示账号、2 个部门、2 个项目、2 个应用和 2 个演示模型。所有演示模型均指向本机确定性替身，不执行厂商推理；演示单价用于讲解平台计量，不是厂商报价。不要在现场切换到真实外部模型。

| 账号 | 展示职责 |
| --- | --- |
| `demo-ops` | 人员开通、用量驾驶舱、调用下钻、费用核对 |
| `demo-new` | 开通演示方案后在线使用；重复开通展示跳过保护 |
| `demo-lin` / `demo-chen` | 已有个人与项目调用的员工 |
| `demo-manager` | 受管项目汇总及项目职责 |
| `demo-app` | 应用独立额度，不持有有效个人权益 |

专用本机演示账号初始口令：`Demo-local-2026!`。原有 `review-*` 账号不变。该口令只用于本机开发演示，正式安装不创建这些账号。

如果需要再次补充数据，停止当前 `pnpm dev`，仍从相同入口启动：

```powershell
$env:REVIEW_PREPARE_DEMO='true'
$env:REVIEW_DEMO_ROUND='2'
pnpm dev
```

相同日期与轮次不会重复发放预算或生成同一批调用。已核对的记录不回滚；需要新待核对样本时把 `REVIEW_DEMO_ROUND` 改为下一个数字（0–999），追加一轮 24 条本地调用。资源继续复用，不删除状态文件，不修改现有业务记录。关闭准备选项后，普通 `pnpm dev` 只恢复工作区。

准备清单位于 `.runtime/review-postgres-<工作区ID>/business-demo.json`，包含资源标识、调用 ID、轮次和时间，不包含完整密钥。准备脚本生成的临时密钥完成后即吊销。

## 15–20 分钟讲解主线

### 1. 开场：为什么需要这个平台（2 分钟）

使用 `demo-ops` 登录，统一使用信标界面。

讲解：“员工需要快速使用 AI，企业需要知道谁能使用哪些模型、费用从哪里扣、异常发生后由谁处理。这里把开放能力、额度和调用证据接在一起。”

运营工作台只讲主要任务，不逐项遍历全部菜单。三版视觉演示放在最后的可选交流环节。

### 2. 运营为同事开通演示方案（3 分钟）

“为人员开通” → 搜索并选 `demo-new` → 下一步 → 选择“演示·办公体验方案” → 预览名单与金额 → 核对人员、模型、金额和期限 → 确认执行。

讲解：“开通决定使用范围和额度，先看影响再生效。已有同方案权益会跳过，重复点击不会再发一份钱。”

当前工作区可能有自动开通基础方案的规则，本步骤开通的是演示专用模型方案。如果之前彩排已经开通过，页面会显示跳过；不重置权益来伪装首次开通。

### 3. 员工实际使用（3 分钟）

退出，使用 `demo-new` 登录 → 在线使用 → **选择“演示·通用助手”** → 展开“回复长度与费用明细”，最多输出设为 **64 Token** → 输入一个示例工单 → 发送。

讲解：“员工直接使用，不需要自己找服务地址和配置密钥。调用前可看费用上限，结束后按用量结算。这里的回复明确来自本地替身，用于稳定展示流程。”

打开调用记录，展示完成状态、Token、费用和来源。现场不展示完整密钥、上游凭据或用户真实正文。

### 4. 从看板发现问题并定位调用（4 分钟）

退出，使用 `demo-ops` 登录 → 用量驾驶舱。

- 展示人员排名、项目／应用归属、模型分布与自然日趋势；数据为实际本地调用积累，无历史流量的日期显示 0。
- 点击“林工（演示）”进入调用记录：时间窗口、主体类型和主体自动带入。
- 打开一条调用详情，讲清结果、计费状态、价格和预占、模型路由及请求编号。
- “返回用量驾驶舱”，确认窗口、维度和滚动位置保留。
- 点击异常数，展示异常分组，不将完成和客户端取消混入异常。

讲解：“看到花费或异常后，可以直接找到对应证据，不必再手工拼筛选条件。”

### 5. 待核对处理与额度预览（4 分钟）

返回驾驶舱 → 点击待核对金额 → 在匹配窗口中选择一条本地演示记录 → 核对并预览。

彩排使用“确认不计费，释放预占”，依据写明：“本地模型替身故障演示，无厂商推理费用，确认释放本地预占。”核对预览后确认，再返回驾驶舱观察待核对数量变化。真实业务须依据上游用量／账单决定结算或释放。

切换归属为项目 → 点击该项目“额度” → 查看金额、期限及影响预览 → 返回修改并取消。本步骤展示可控操作入口，不为了演示反复追加预算。

### 6. 给解决方案同事的补充（3 分钟）

- `demo-manager` → “项目用量”：只展示本人、负责应用及 active 受管项目范围；本轮没有扩张调用明细权限，运营下钻入口不向经理显示。
- `demo-app` → 应用：展示两个应用的独立额度和接入任务，说明应用使用不依赖负责人个人权益。
- 介绍模型服务／池、用途密钥、预占结算与审计关系。已有真实模型联调证据可单独说明日期与范围，不把本地固定回复当作真实推理。

收尾：“平台让企业能开放能力、看清费用和处理异常。客户身份接入、目标部署及容量按具体项目验证。”

## 现场检查与恢复

- 提前完整走一遍这条主线，保持两种角色的账号清单可用；本轮自动彩排与截图见验证记录。
- 筛选无数据时，确认时间窗口及所选演示模型，不把空窗口解释为没有能力。
- 待核对已处理完时，追加下一轮本地样本；保持已处理记录可追溯。
- 接口失败时展示错误状态与重试；本轮实现会禁用旧数字的 CSV 导出。
- 演示结束后保留数据。下次仍运行 `pnpm dev`，不用重建数据库或重新配置外部模型。

自动回归入口：构建后运行 `node scripts/check-web.mjs --postgres --demo`，在隔离 schema 中准备同一套场景并彩排，不修改日常工作区。日常工作区的彩排只操作上述专用演示账号及记录。
