# 开发边界与验证分层

## 当前目标

当前目标是完整首版产品，具体缺口以 [完整实现清单](IMPLEMENTATION-STATUS.md) 为准。最初的本地纵向闭环仍作为底层回归：

`员工/API Key -> 业务后端授权 -> 数据面转发 -> 测试模型 -> 用量事件 -> 额度预占/结算 -> 调用日志`

## 业务边界

- 业务后端是组织、权益、额度账本、结算、API Key 元数据和调用日志的权威来源。
- 个人额度、项目额度和应用额度使用不同的额度来源类型，不能互相补扣。
- 模型池是授权范围，不是算力对象；`follow` 和 `specific` 语义不能合并。
- `GatewayProvider` 是唯一的网关适配边界；业务模块不得依赖 Higress 内部对象或管理数据库。
- 本阶段不读取生产密钥、不发送真实模型请求、不修改旧项目。

## 三种验证层级

1. **本地模拟**：内存账本 + `gateway-sim` + `test-model`，验证业务状态机和错误路径。
2. **Mock 验证**：使用替身 Provider 或 HTTP mock，验证合同、幂等和可替换性。
3. **真实 Higress 验证**：固定隔离版本、虚拟凭据和测试模型，单独记录配置同步、非流式、流式、失败与事件采集证据。本阶段尚未执行。

开发 PostgreSQL 验证单独记录：它证明真实数据库事务、并发和重启持久化，与数据面是否为 Higress 无关。`pnpm check:postgres` 在一次性专属 schema 内运行并清理；不得把共享演示额度重置作为常规测试前置条件。

网关的故障 HTTP 替身位于 `postman/mocks/test-model/`，来自本仓库的测试模型响应契约，可直接启动或经 Postman simulation 启动。它不代表任何真实模型厂商实现。

## 已实现与待补齐

- 个人、项目成员与应用批次精确隔离。项目总预算、审批、成员原批次分配和项目结束余额回收已实现；已准入请求仍按原来源结算，释放金额进入结束回收记录。
- 调用追溯记录平台请求 ID、受支持的上游请求号头（`x-request-id` / `request-id`）和客户端显式重试关联；不保存提示词、回答、密钥或完整响应头集合。
- 连接验证是平台诊断流量：记录运行、逐映射用量、价格快照和内部成本估算，不扣人员/项目/应用额度，也不进入员工调用统计和业务告警分母。
- 存量方案迁移只允许同一方案、同一发放周期的旧版本权益迁到当前版本；保留余额、期限、来源与已发周期，不补发额度。
- 用量未知的取消、超时和中断保留预占并标记 `pending_review`；租约过期、迟到完整用量和运营原批次核对已实现。
- 重复授权有重放标记，模拟网关拒绝重复转发；尚不重放原模型正文。
- 数据面提供 OpenAI 兼容的 `/v1/chat/completions` 与 `/v1/models`，外部工具可用平台签发的用户密钥接入；`/v1/models` 只做发现，每次调用仍重新校验授权。连接阶段失败允许一次有界重试，仅在明确未发出请求字节时进行，因此不会重复计费。
- 控制面结算失败后持久化事件保持待补发；本地网关日志恢复已验证，持久卷/断电/跨实例运行仍需单独验收。
- `/api/v1/calls` 和演示额度接口要求服务令牌。Web 使用密码会话和对象职责范围；当前单企业工作空间不作为多租户 SaaS 隔离证明。

本地模拟通过不代表 Higress 已通过 PoC，也不代表 PostgreSQL/Redis 生产部署已经验收。
