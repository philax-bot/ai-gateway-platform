# 人工审查入口

本轮审查重点是运营和员工能否独立完成任务：能看懂当前状态、找到主要动作、确认实际结果，并在失败时恢复处理。用户最新决定先不处理 Higress；当前集中核验外层产品，不以 Higress 选型作为本阶段前置条件。

## 当前推荐：保留人工审查数据

最新版本在 [localhost:5176](http://localhost:5176/)，包含密钥筛选与批量管理、保留策略、企业名称/默认池确认和操作记录检索。使用下方五个审查账号，初始密码为 `Review-local-2026!`。使用独立 PostgreSQL schema；页面明确显示“审查数据会保留，重启后可继续”。较早的 5173/5174 内存实例已停止，当前统一使用 5176。

当前已进入人工核验交付阶段。核心业务已有分项浏览器和数据库回归证据，本轮另补 9 个页面状态 × 5 种宽度的 45 项布局检查及键盘焦点检查，结果见 [交付复核](IMPLEMENTATION-STATUS.md#人工核验交付复核)。这些检查不能替代你的实际体验判断；按下方任务走一遍，指出具体卡点即可，无需先读设计文档。

从项目根目录启动或在停止后恢复：

```powershell
pnpm dev
```

使用 `apps/control-plane/.env`（或进程环境）中的开发数据库连接，只写脚本生成的专属 `agp_review_<uuid>` schema，不采用已有共享或正式 schema。默认 Web 5176、控制面 4301、网关 4300、模型替身 4310，全部监听本机；模型验证和推理仅使用本地替身。首次创建固定场景，此后不会重建账号、重置密码或再次发放初始额度。

按 Ctrl+C 停止后保留数据、日记及 `.runtime/review-postgres.json`。下次沿用同一命令和端口；不要删除状态文件或审查 schema。已有数据缺失、身份不符或另有运行进程时会拒绝启动，不悄悄重置。需要另一套独立数据时设置新的 `REVIEW_WORKSPACE` 名称和四个空闲端口，不覆盖当前工作区。

当前 5176 增加“密钥筛选演练（本地替身）”示例应用和两把演练密钥；原应用首次签发场景不受影响。可从“配置与排查 → 密钥与接入”按“密钥筛选审查组”检索，再核对状态、原因及逐把历史。详情与筛选不显示完整密钥。两把演练密钥已用于批量停用和吊销验证，不用于工具接入；接入审查仍使用原应用新签发的密钥。

同一浏览器的 `localhost:5174` 和 `localhost:5176` 共用主机 Cookie，切换可能需要重新登录。`127.0.0.1` 的 Cookie 独立；当前不需要启动额外实例。

保留策略审查：review-ops → 配置与排查 → 企业设置 → 通知、告警与会话保留。当前为 90 天、仅手动执行；先“重新检查”读取分类数量，再按需调整策略。策略预览显示期限和执行方式的前后变化；保存手动策略不删除记录。开启自动执行后，下一轮维护可能开始按策略清理，之后每天按北京时间去重检查。手动清理需填写原因、重新核对分类数量后另行确认；无可清理记录时不提供无意义的执行按钮。未读通知、未完成事项和活跃告警保留；账本、调用元数据、审批、开通和操作审计继续保留。当前审查库未执行清理，数据库执行验证使用单独的临时 schema，详见 [保留策略验证](VALIDATION-RETENTION-2026-10-20.md)。

操作记录审查：review-ops → 配置与排查 → 企业设置 → 查找操作记录。默认收起；可按关键词、操作人、操作及北京时间范围筛选。输入“演练 · 旧工具甲”、选择“批量调整密钥”，可找到两次批量变更及逐把脱敏结果。清除筛选后可翻页查看全部保留历史；新增记录通过“刷新最新记录”进入当前查询。

企业设置审查：同页“调整企业名称”或“调整默认池” → 填写 → 预览。确认页显示服务端当前值和目标值，返回继续编辑会保留草稿，取消不保存。默认池仅影响后续默认选择，不迁移已有资金或批次。本次浏览器检查仅预览并取消，未保存企业设置。

本轮已验证的真实模型事实：DeepSeek 官方 `deepseek-flash` 连接验证通过；非流式、SSE 和正文调用各 1 次，均返回真实 usage 并正确结算；`review-employee` 个人余额从 19.99941 降至 19.99835（三次费用合计 0.00106 元）。DeepSeek 未返回 `x-request-id` / `request-id`，因此上游请求号显示“上游未提供”；该模型返回 `reasoning_tokens`，短 `max_tokens` 可能只产出 reasoning 而无正文。

自动化浏览器证据：`pnpm check:web`（本机 Chrome headless，46 项断言）；截图见 `docs/validation/screenshots-2026-10-23/`。本轮详细结果、备份路径与未执行项见 [首版缺口实施验证](VALIDATION-2026-10-23.md)。

## 建议依次审查

| 任务 | 操作路径 | 应看到的结果 |
| --- | --- | --- |
| 员工首次使用 | review-employee → 在线使用 → 输入短任务 → 发送 | 默认选择可用模型；显示预占上限、固定模型替身回复；额度/调用记录随后更新；无需先创建密钥 |
| 项目用途 | 同账号切换到“项目 · 知识助手试点”再发送 | 项目和个人余额分别变化，页面始终显示当前用途 |
| 审批失败恢复 | review-ops → 申请与审批 → 待开通同事的失败申请 → 修正执行内容，选择“日常办公标准方案”并填写依据 → 预览确认 → 执行生效 | 保留申请 12 元及原批准 8 元；修正本身不发款，执行后才生效；当前状态、责任人、意见与下一步持续可见 |
| 生效后的员工 | review-new 登录 → 首页 → 在线使用 | 看到已开通和可用余额，可直接发送；“我的申请”显示已生效 |
| 经理审批 | review-manager → 首页“处理申请”或“申请与审批” → 员工项目额度申请 → 核对并审批 → 选择试点预算、批准 5 元 | 审批与执行记录分别保留；原预算减少 5 元，员工项目余额增加 5 元；额度沿用所选预算到期日，无需重复填写日期 |
| 项目连续操作 | 同经理 → 工具与协作 → 项目 → 管理成员与额度 → 分配给成员 | 根据缺口显示下一步；分配成功后详情自动更新；再打开表单使用最新预算；批次和历史按需展开 |
| 应用接入 | review-app → 首页“进入应用” → 签发应用接入密钥 → 保存一次性值 → 接入指引 | 即使个人未开通，仍可看见应用模型和额度；个人使用为折叠的按需入口；密钥表单和确认页绑定该应用，只需核对名称和日期；指引提供地址、模型与 PowerShell 示例 |
| 应用短请求 | 将刚保存的密钥配置到本机受控 `AI_API_KEY` 环境变量，按指引发短请求 → 应用页刷新 | 应用记录出现调用，费用只从应用额度扣除；固定示例回复不能当作真实模型效果评测 |
| 人员开通 | review-ops → 为人员开通 → 选择未持有方案的人员 → 选方案 → 核对并确认 | 有明确逐人名单、金额、到期日和跳过原因；完成页给出员工登录在线使用的下一步 |
| 驳回后重提 | 使用一条新的申请，运营驳回并说明原因 → 申请人查看意见 → 修改后重新申请 | 原申请和意见保留，新申请带回原内容供修改 |
| 缺配置时继续任务（新版） | review-ops → 为人员开通 → 开通设置 → 创建方案，填写名称与金额 → 就地新建模型池 → 新建模型服务 → 新建模型定义，再逐层保存返回 | 各层草稿保留，新对象自动选中；服务先保存再验证，失败可修改后继续；未验证的服务不能默认开放；仅保存配置不会向人员发款 |
| 成员资料草稿（新版） | review-ops → 组织与成员 → 编辑成员，填写姓名与标签 → 就地新建组织 → 返回 | 新组织自动选中，其他草稿保留；取消子表单保留最新父草稿，取消父表单不会保存成员修改 |
| 组织移动与停用（新版） | review-ops → 组织与成员 → 编辑与影响预览；当前实例可查看“规则接收部”及下级 | 上级选项排除自身和下级；预览包含全部下级人员、访问和周期发放变化；若会新增金额，按钮明确“确认调整并发放”；停用后列表区分本级停用与受上级影响，恢复不重复发放本月额度 |
| 长表单与确认页（新版） | 打开模型服务编辑或组织调整，滚动正文 | 弹窗标题与底部返回/确认按钮持续可见；提交仍执行表单必填校验，正文滚动不移动操作栏 |
| 模型准备 | review-ops → 配置与排查 → 模型配置 | 首屏只显示当前阶段和主要动作；固定场景已就绪，可直接继续人员开通；已有配置按需展开。缺配置、失败修复、价格未知和未开放状态已在独立场景检查，见 [安装与模型引导验证](VALIDATION-INSTALLATION-2026-10-19.md) |
| 运行监控 | review-ops → 配置与排查 → 运行监控 → 展开“采集状态与处理” | 默认首屏显示关键读数和待处理事项；无流量明确提示证据不足。可暂停刷新后手动检查采集；检查不发放额度或调用模型。统计故障、知晓、真实时间恢复及再次故障已在独立数据库浏览器环境验证，见下方记录；不需要在人工审查实例制造数据库故障 |

审查每条任务时，记录：使用账号、从哪页开始、想完成什么、卡在哪一步、预期与实际结果。尤其关注是否需要猜测系统概念、重复选择已知对象、离开页面寻找配置，或执行后无法确认结果。

## 当前边界与待完成项

- 这是供集中人工审查的本地版本，默认模型回复为明确标识的固定替身，未连接真实模型和真实 Higress。显式设置 `REVIEW_ALLOW_UPSTREAM_REQUESTS=true` 后，数据面可调用已配置且验证通过的外部模型服务，产生真实厂商费用。

- 新版已补主要配置引用的就地创建与草稿返回、完整下级组织影响、固定弹窗操作栏和独立采集故障处理；证据见 [配置流程验证](VALIDATION-CONFIG-FLOWS-2026-10-19.md)、[组织调整验证](VALIDATION-ORGANIZATIONS-2026-10-19.md) 和 [采集故障验证](VALIDATION-COLLECTION-2026-10-19.md)。正式运行交付和完整页面/权限验收仍有未完成项，见 [完整状态](IMPLEMENTATION-STATUS.md)。
- 外层版本可审查后，再 clone Higress 做隔离评估；接入、扩展或自研的结论以验证结果决定。正式数据面可靠性和运维验收不会由本次页面审查替代。
