用户已选择首期采用每用户独立 Octop 实例，**85 项本地检查通过**。联调使用固定上游 commit `890111b7879665840414ca28ab168b05b0db0921`、独立进程、独立 `OCTOP_HOME` / SQLite / JWT 签名秘钥、独立 Provider 及平台签发的个人 Key；网关和平台控制面仍共用同一套业务账本。

每个实例均有一个本轮独立生成凭据的运维管理员和一个对应的普通用户。管理员不面向最终用户开放，普通用户不具备 Provider 管理权限。实例之间不复用管理员 Token、用户密码、JWT 签名秘钥或存储目录。安装与配置直接调用上游已有 API，没有修改 Octop 业务源码。

固定上游、依赖虚拟环境和本地替身可以共用；它们不包含客户 Key。运行时配置和凭据分别存储在各自临时 home，测试结束删除。

## 验收路径

- **配置可见范围**：每个实例的普通用户只能列出本实例唯一的 Provider 和对应 Key。此版本仍会向本实例普通用户返回该 Key，独立实例没有改变上游返回语义。
- **跨实例认证**：三个用户的 Token 对其他两实例的 Provider / Agent 请求均返回 401；Alice 与 Bob 的跨实例聊天 WebSocket 连接也被拒绝。
- **并行调用**：Alice / Bob 并行执行文本对话和 `read_file` 工具往返，模型分别收到各自 workspace 的固定标记。对每笔带所有者标记的真实网关请求，按请求 ID 核对平台 `subjectId` 与 `credentialId`，不能仅凭两个账户都有扣款就判定隔离成立。
- **辅助模型**：两人的 `/api/text/assist` 采用自动模型选择，各自成功产生一笔、且仅一笔归属自己的个人 Key 的调用。首次关闭记忆抽取、知识库、MCP 和委派，其他辅助能力仍需逐项接入。
- **单实例停止与重启**：停止 Bob 的本轮进程树，确认其端口返回 `ECONNREFUSED`；停止期间 Alice 继续完成对话。Bob 使用原 home 重启后保留 Provider，原 Bob 会话可继续使用，Alice Token 仍被拒绝。
- **额度不足**：Low 收到可见错误，没有请求到达模型，拒绝记录不计费、不预占，初始余额不变。上游仍会将该错误显示为“鉴权失败”并重试，交互问题尚未修复。
- **显式取消**：Alice 的 WebSocket cancel 使网关保留 `client_cancelled / pending_review` 和未知用量预占；未按零费用结算。
- **Key 停用**：Alice Key 停用后，Alice 的对话和模型发现受阻，Bob 的独立实例继续成功。
- **计费与清理**：按每个成员分别核对余额 + 确认费用 + 待核对预占 = 初始额度；结束时检查结算 outbox 无 queued / blocked。仅停止、清理本轮创建的进程与运行目录。

停止脚本按自身创建的 PID 树操作。Windows 的虚拟环境 Python 启动器可能另有解释器子进程，因此 PID 变化不足以证明重启；端口确实关闭后才开始恢复验证。

模型为脚本内的确定性 HTTP 替身，网络约束入口限制 Octop Python 进程只连接回环地址。它验证真实 Octop、SDK、网关和账本的集成，不证明模型推理、真实供应商兼容性或生产容量；没有调用真实模型，没有厂商费用。

本轮替身收到 15 次生成请求：1 次平台独立连接验证、2 次 Octop Provider 探测、2 次辅助模型调用，以及 10 次对话/工具/重启后调用/取消请求。固定用量与价格沿用首次验证，每笔确认费用为 39 微元；所有金额均为隔离测试额度。

## 复跑

已有上轮固定源码和依赖缓存时直接执行：

```powershell
pnpm check:octop
```

默认即每用户独立实例模式，启动本地临时环境并在结束时清理。源目录可作为位置参数传给 `node scripts/check-octop.mjs <source-directory>`；仍要求固定 commit、未修改的上游已跟踪源码，以及其中的 `.venv/Scripts/python.exe`。

新环境的缓存准备步骤见 [首次验证的准备命令](OCTOP-INTEGRATION-2026-10-28.md)。如果要重新诊断共享实例的旧问题，显式执行：

```powershell
node scripts/check-octop.mjs --shared
```

`--shared` 仅用隔离测试 Key 复现旧问题，不能用于正式托管。两种模式均生成唯一的 `.runtime/octop-results/*.json`；使用 `OCTOP_REPORT_PATH` 可指定尚不存在的新文件，不覆盖历史报告。`success` 是对应检查流程是否完成，生产可用性单独记录。

## 后续边界

后续按每用户实例方案推进，不再把共享实例的 Provider 二开作为首期前置条件。正式托管还需要：

1. 平台稳定用户 ID → 实例的服务端映射，以及统一登录、实例级路由与 WebSocket 鉴权。不能信任客户端提供的 owner、端口或 home。
2. 用户实例生命周期、Key 签发时交付、失败补偿、轮换和撤销。管理员凭据由运维侧保管，不交给用户；不能从平台哈希取回旧 Key。
3. 每用户的容器/执行身份、文件卷权限和工具沙箱；限制执行资源与网络，避免同宿主账户下任意读取其他实例的 home。
4. 受控真实模型验收，再按授权执行目标主机的 TLS、容量和恢复验证。

本轮没有实现云端实例管理器、SSO、真实模型调用或部署，也没有改动现有审查实例及无关业务改动。
