## 本轮实现

- 显式正式模式的配置前置检查、空种子、安装口令与初始管理员，正式/开发安装模式互斥。
- 迁移版本、文件名、内容摘要及执行时间账本；并发启动串行化；失败事务回滚和历史篡改拒绝。
- 正式模式网关仅使用受控准入路由，要求独立绝对持久目录。
- 模型页改为登记/启用、连接与完整价格、开放范围、人员开通的当前任务；已有配置按需展开。
- 运营首页、方案候选与模型页采用一致可用性判断；服务状态/共享容量按需展开；成员默认组织不依赖演示部门。
- 安装成功而自动登录失败时可继续普通登录，避免重复执行首次初始化。

## Chrome 实际操作

独立内存场景使用 5175 / 4201 / 4200 / 4210，配置变更只作用于该场景。默认账号和模型来自 `pnpm review`。通过受控命令先准备停用、不可达来源、价格未知及池未开放状态，再在页面实际操作恢复。

| 场景 | 可见结果 |
| --- | --- |
| 全部已登记模型停用 | 提示启用已有模型，打开原模型编辑；另有登记新模型入口，没有误称已就绪 |
| 无有效模型服务 | 连接服务表单预选当前模型，显示其上游标识及待确认价格 |
| 未验证来源 / 本地不可达地址 | 主要动作是验证连接；失败标为“连接未通过”，提供修改同一服务入口；详情折叠 |
| 浏览器修正地址并验证 | 保存确认、验证均执行；重新验证成功后不再保留旧的连接失败提示 |
| 连接通过但输入价格未知 | 仍停留在确认价格步骤，首页不认定准备完成；明确 0 可作为价格，空值不能作为免费 |
| 价格完整但池未开放 | 当前动作变为调整并开放原池；预览显示旧/新来源及关联方案、权益、项目、应用数量 |
| 确认开放 | 立即变为已接通并开放，主动作进入人员开通；默认不展开四类管理表格 |

证据：[全部停用](validation/2026-10-19-model-register.png)、[连接失败](validation/2026-10-19-model-connection-failed.png)、[价格待确认](validation/2026-10-19-model-price-needed.png)、[待开放](validation/2026-10-19-model-open-needed.png)、[已就绪](validation/2026-10-19-model-ready.png)。
