# 权限变更与重试验证 · 2026-10-20

本轮修复已完成的业务命令在幂等重试时绕过当前权限的问题。应用交接、项目经理变更或运营降权后，旧操作者以前仍能通过原幂等键取得旧操作结果；直接详情接口已拒绝访问，但重试路径提前返回历史结果。当前在预览、首次执行和返回历史结果前都核对当前职责，不重新执行已完成的资金或签发动作。

浏览器证据：[保留草稿与恢复入口](validation/2026-10-20-permission-draft.png)、[最新审查首页](validation/2026-10-20-review-home.png)。5175 仅用于独立验证，已经停止；最新完整审查入口为 [127.0.0.1:5173](http://127.0.0.1:5173/)，保留原五账号及固定场景，没有把验证中的交接混进默认场景。

## 当前权限入口

| 入口 | 服务端范围 |
| --- | --- |
| `/api/v1/auth/me`、全部 `/api/v1/platform/*` | 每次检查有效会话和当前人员/组织状态，页面菜单不作为授权依据 |
| 工作空间快照 | 运营读取业务元数据；其他人员读取本人权益/额度、参与或负责的项目、负责的应用与密钥；不返回密码散列或密钥散列 |
| 项目详情/成员候选 | 运营和当前经理管理；普通成员只取得自己的成员额度，不取得项目预算、他人批次或管理审计；成员候选只向管理者提供有效企业成员 |
| 应用/密钥详情 | 运营和当前所有者；应用交接同时移动密钥管理归属，旧所有者立即失去新读取与重试权限；内部在线临时密钥不通过公共管理入口操作 |
| 调用日志 | 运营查询全量元数据；其他人员查询自己和自己负责应用的调用；项目经理身份不自动取得他人的对话或全量调用权限 |
| 审批 | 申请人可看自己的记录，处理者按当前职责与禁止自审规则核对；执行还要求是当前批准人；交接后重试也重新核对 |
| 预览和业务命令 | `command-authorization.ts` 核对当前职责；数据、金额、期限及状态仍由实际动作检查；未知命令直接拒绝 |
| 模型、组织、人员、方案、发放、运营设置、监控与维护 | 运营职责；不因能进入个人空间、项目或应用而放开 |
| 旧调用接口与内部策略/结算/同步 | `ServiceTokenGuard`，浏览器登录会话不能替代服务令牌；网关身份和用途按受控凭据校验 |
| 在线临时身份/报价 | 当前登录人自己的个人或项目用途；不接受正文中的他人身份替代登录人，不要求本人手工建长期密钥 |

这张表记录本轮逐项查看的入口与实现约束；源码分派表中的 32 种当前业务命令都有显式授权分支，未知类型拒绝。不把新增 17 项检查当成每个接口、每种角色组合的穷举证明。人员停用、范围调整、来源批次、日志和应用独立性继续由原回归覆盖；更多业务页面与人工验收仍须按完整清单继续。

## 人能处理的失败

权限变化显示中文原因与恢复动作；预览失败会刷新工作空间，而不会反复留下旧职责。草稿仅保留在当前窗口，关闭后不提交。登录必需、会话过期、管理员权限、对象交接、陈旧预览和服务暂时不可用分别说明；提交后连接不明时提示先刷新确认结果，再决定是否重试，不自动重发资金命令。

## 边界

本轮为本机、仓库模型替身与隔离开发 PostgreSQL，未使用真实模型、正式凭据或正式数据库。新的审查实例仍使用内存，停止/重启会清空人工操作；本轮环境重启后的旧实例已结束，不能把历史文档中“保留旧数据”的描述当成现时运行状态。
