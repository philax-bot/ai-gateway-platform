# 人工审查版本验证 · 2026-10-19

用户当前阶段决定：先完成外层任务和交互并交付人工审查入口，之后再 clone Higress 评估接入或自研数据面。完整目标尚未标记完成。

## 本轮交付

- `pnpm review` 从当前源码构建，启动仅监听本机的内存控制面、仓库模型替身、模拟网关与 Web 构建；创建五个公开本地测试账号和固定的人员、审批、项目及应用场景。
- 审查用的 Web 构建复制到本次独立运行目录，普通构建不会替换已启动的页面。端口占用会报错并停止，不接管其他进程。日记保留作为本次审查证据，退出/重启会丢失内存业务操作。
- 页面明确显示审查模式和模型替身；本地回复为固定示例，不用于评价真实智能模型效果。
- 审批改为事项队列和当前处理内容，持续显示节点、当前责任人、申请/批准值、处理意见和恢复动作；当前操作权限由服务端返回。最后一项生效后保留完成详情。驳回/撤回可带回原内容创建新申请。
- 应用接入按模型、额度、密钥、工具验证推进；负责人无需个人使用权益。应用详情服务按当前负责人/运营限定范围，返回真实账本来源和状态，不依赖最新若干日志猜测余额。
- 人员首页优先呈现经理待处理申请或负责的应用；个人使用可按需开通。用途绑定的密钥表单只要求名称和日期，确认页明确对象和扣费用途。

## 已执行证据

- `pnpm test`：控制面 49、导入解析 2、网关 7 项测试通过。新增应用详情测试覆盖无个人权益、独立额度、价格/模型问题、过期资金、停用、交接即时权限及不泄露完整密钥。审批既有用例增加当前操作权限断言。
- `pnpm check:postgres`：215 项 HTTP 断言通过并删除独立测试 schema，共享演示余额未变。包含应用详情的原来源账本读取、无关人员拒绝、交接后旧负责人失去权限和申请人能力字段。
- Web TypeScript 和构建通过；OpenAPI YAML 解析通过（不等同于正式 OpenAPI lint）。
- 实际运行 `pnpm review` 创建固定场景和五个账号，之后在 Chrome 走通下列操作。

| 场景 | 浏览器实际结果 |
| --- | --- |
| 原批准方案错误 | 运营页显示申请 12 元、批准 8 元及执行失败；先修正，再显式执行，原申请保留 |
