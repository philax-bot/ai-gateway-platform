# Higress 隔离 PoC 验收清单 v0.1

日期：2026-10-16。目标：判断 Higress 是否适合成为本产品的数据面实现，而不是证明产品已经完成生产部署。

## 1. PoC 范围

使用一个隔离的 Higress 版本、一个 OpenAI 兼容测试模型服务、一个测试员工、一个测试项目和两种测试凭证。只使用虚拟额度和非生产密钥；所有请求与费用均标记为测试数据。

最小链路：

```text
创建模型服务 → 创建模型池 → 开通个人权益 → 策略授权
→ Higress 转发 → 非流式 / 流式响应 → 事件采集
→ 额度预占 → 结算 / 回滚 → 调用日志
```

## 2. 必须通过的验收项

| 编号 | 场景 | 通过标准 | 证据 |
| --- | --- | --- | --- |
| P01 | OpenAI 兼容非流式 | 请求、模型名、错误格式和响应字段可被现有客户端正确解析 | 请求/响应脱敏记录 |
| P02 | OpenAI 兼容流式 | 可关联同一 requestId，正常结束和中断均能产生结算事件 | SSE 事件与结算记录 |
| P03 | 请求前授权 | 策略能区分员工、应用、个人用途、项目用途和模型；拒绝有稳定 reasonCode | 授权 API 记录 |
| P04 | 额度不足 | 请求不进入模型服务，不产生消费；重复重试不重复预占 | 网关日志 + 账本 |
| P05 | 并发预占 | 并发请求不能透支同一批次；同一幂等键返回同一结果 | 并发测试报告 |
| P06 | 上游失败 | 超时、鉴权失败、模型不存在、连接失败分别记录；按规则释放或待核对 | 失败分类和账本状态 |
| P07 | 客户端取消 | 取消有独立状态，不被误记为上游故障；结算规则可复现 | 流式取消证据 |
| P08 | 用量字段 | 输入、输出、缓存 Token、上游 request id 和耗时可采集；缺失显示 pending_review | 事件样本 |
| P09 | 模型池变更 | 跟随模式扩大，指定模式不扩大；配置发布有版本、延迟、失败和回滚状态 | 策略版本与同步记录 |
| P10 | 服务停用 | 新请求被阻止，授权、余额和历史调用保留；重新启用可恢复 | 前后对比记录 |
| P11 | 配置失败 | Higress 发布失败或部分成功不会被标记为已生效，能够重试/回滚 | provider 操作记录 |
| P12 | 安全边界 | 员工 API Key 不可调用 Higress 管理接口；管理凭据不出现在日志和前端 | 脱敏日志与权限测试 |
| P13 | 性能开销 | 策略和事件链路的延迟、错误率、吞吐在预先约定的测试阈值内 | 对照压测结果 |
| P14 | 可替换性 | 业务后端只依赖 GatewayProvider 合同，切换模拟 provider 不改额度和权益逻辑 | provider contract test |

任何 P02、P05、P06、P08、P09 或 P11 未通过，都不能直接把 Higress 锁定为生产数据面；应先记录缺口和替代方案。

## 3. 重点对比三种实现路径

| 路径 | 适用条件 | 成本与风险 |
| --- | --- | --- |
| Higress 外部鉴权/插件 + 旁路结算 | 网关能提供请求前检查和可靠事件 | 首选；依赖扩展点和事件完整性 |
| Higress 小范围适配或补丁 | 仅缺少稳定扩展点，核心生命周期仍适合 | 需要维护版本、补丁和升级回归 |
| 自研数据面 | Higress 无法可靠支持核心请求生命周期，且规模与团队有能力承担 | 成本最大；必须自行负责代理、连接、TLS、流式、限流和安全 |

PoC 期间不做完整自研网关。只有在 P02、P05、P06 或 P08 等核心项持续失败，且旁路方案也无法满足一致性时，才进入自研数据面评估。

## 4. 记录格式

每次测试至少保存：Higress 版本、适配器版本、模型服务版本、策略版本、请求 ID、幂等键哈希、主体类型、用途、模型、响应状态、结束原因、Token 字段、预占/结算状态、延迟、错误分类和时间戳。不得保存明文 API Key、提示词或回答正文。

结果只分为 `PASS`、`PARTIAL`、`FAIL` 和 `NOT_RUN`。HTTP 200、网关配置返回成功或模型有响应都不能单独作为端到端通过证据。

## 5. PoC 结束后的决策门

- **通过**：实现 `HigressProvider`，锁定隔离版本，补齐生产安全和运维方案，再开始正式前后端纵向开发。
- **部分通过**：保留 Higress 做代理和基础保护，将缺口放到策略/结算旁路，重新评估延迟和一致性。
- **失败**：不急于修改核心；先比较补丁、上游贡献和其他数据面实现，再决定是否自研。
