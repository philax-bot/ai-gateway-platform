# Higress 业务 API 闭环与在线会话修复

业务闭环验收通过，并修复了一个实际权限缺口：退出登录后，该会话签发的短期在线身份原先仍能继续生成。现在临时身份由服务端绑定到签发会话，注销后拒绝新的调用；其他登录会话及普通 API Key 继续遵循各自的授权。已准入请求仍按原价格结算。

## 验收范围与结果

运行命令：`pnpm check:higress:business`。这是隔离验收入口，日常启动仍为 `pnpm dev`。

使用真实固定镜像 Higress、独立 PostgreSQL schema、内部容器网络和确定性模型替身。全部操作通过真实登录 Cookie、业务 API 和网关 API 执行；不读取 DeepSeek 凭据、不发送真实模型请求。它是 API 流程验收，未替代界面人工体验、生产部署或高可用验收。

## 会话缺口与修复

旧实现创建一个最长五分钟的内部 Key，但没有记录签发会话；退出登录只删除登录会话，Key 仍可访问网关。最初把个人权益撤销与注销叠加的用例会遮住这个问题。改为项目在线身份“先成功、再注销、再拒绝”的对照后，真实 Higress 仍观察到退出后的请求，PostgreSQL 也记录了确认费用，见 [修复前后对照](../validation/higress-business-2026-10-29/session-regression.json)。

新实现从认证请求中提取会话令牌，在签发事务内重新核对会话归属和有效期，只保存私有 SHA-256 关联。临时身份到期日取会话到期、最长五分钟及人员有效期中的最早时间。注销在同一业务事务中吊销该会话对应的内部身份并同步凭据投影，签发与注销的并发顺序不会留下新的可用身份。

私有关联不进入公共 Key、工作区响应或幂等结果。旧的无会话关联内部身份拒绝继续授权，前端可按正常在线使用流程重新获取身份。单元测试另确认：会话失效后不能再签发身份；伪造归属不生效；注销不释放已准入请求的费用。普通用户签发的 API Key 不采用这个会话生命周期。

首轮另有一处验收器的预期错误：跨范围调用查询按现有合同返回 200 空结果，而非强制 403/404。修正断言后同时验证负责人能读到原记录、他人只能读到空结果。原失败记录分别保留，不改写为通过。
