# Higress 接入收尾与恢复验收

本轮范围是建立可独立构建的接入基线，验证本地 Higress/PostgreSQL 链路的持续负载与故障恢复。生产部署、真实模型持续负载和高可用不在本轮验收范围。

## 代码基线

`8774816` 提交正式 Provider、持久同步状态和统一开发入口。暂存内容单独导出后，contracts、control-plane、gateway-sim 三个包构建通过，控制面 137 项测试通过。提交前检查了实际配置密钥，不包含根 `.env`、数据库连接串或运行时凭据。原工作区的 Octop、Web 和其他性能改动保持未提交状态。

## 就绪检查与本地网络

第一轮版本探针由本地插件直接应答。受控复现证明：模型已停机时它仍会返回成功，而主转发路径返回 503。因此，版本应答不能证明上游集群可用。

新增认证后的 `/runtime/ready/<managed-route>` 观察接口，仅读取 Envoy 的主路由、实际引用的集群、健康端点，并尝试建立 TCP 连接。它不发送模型 HTTP 请求、不生成 Token，也不返回端点地址或插件凭据。`pnpm dev` 自动启用 `HIGRESS_REQUIRE_RUNTIME_READY=true`，Provider 在确认版本后继续检查该观察结果，未就绪则维持 `pending`，超时保留原生效版本。

实际诊断还发现两个本地运行因素：Podman 重启会更换动态 IP；固定镜像的 `dnsRefreshRate` 默认是 200 秒，超过 Provider 20 秒的确认窗口。本地运行器给自有容器设置固定地址，将 DNS 刷新配置为 5 秒，并保留 DNS 自身 TTL 行为；已有容器通过停机后的网络重连调整，不删除 `/data` 和业务数据库。管理中继和替身启动文件会重新写入，避免中断初始化后复用缺文件的容器。

原首次 DeepSeek 503 缺少当时的传输诊断，不能把本轮发现当作其唯一根因。新的访问日志记录请求 ID、响应码、路由、响应标志及传输失败原因，不记录请求正文或凭据。

## 配置操作恢复

在途切换测试还暴露了多个 AI Proxy WasmPlugin 并存时的路径改写故障：控制面已采用新模型及新价格，后端却收到未改写的版本路径并返回 404。实现改为一个共享 `atlas-ai-proxy` 插件，使用不可变路由版本的匹配规则，保留旧版本规则并通过管理 API 的版本条件合并更新。旧流保留原模型、原价格，新准入使用新模型与新价格；验证不会把 404 当作扣费成功。

配置探针的兜底目的地改为 Higress 自身的回环拒绝端口，插件尚未加载时也不会访问真实上游。内部跳转凭据使用专用 `x-atlas-hop-token`，并在转发前移除；真实上游的 Authorization 仅由 AI Proxy 注入。公开客户端仍使用原 API Key 和 OpenAI 兼容接口。

失效租约的旧发布者不能在新操作完成后覆盖当前生效版本。新的单元测试阻塞旧发布、使租约失效、完成新发布，再释放旧发布，检查生效版本保持为新版本，原操作 ID 和失败结果仍可重放。

启动恢复会重新观察数据库中已生效的路由。若运行时配置丢失，使用新操作重新发布原不可变版本；不能仅凭数据库中的历史 `applied` 判为当前运行时已就绪。

## 验证方法

```powershell
pnpm check:higress:stability
```

默认持续负载为 180 秒、4 个用户、8 并发，允许 `--duration=60..1800`。使用独立 PostgreSQL schema 和无外网路由的容器网络，全部生成由确定性 HTTP 替身提供，真实模型请求为 0。

专项路径包括 35 秒持续流、在途流期间切换模型及价格、仅中断本次控制面的 PostgreSQL TCP 连接、流中停止并恢复 Higress，以及持久化 `pending` 后终止控制面。配置中断测试在进程终止后推进独立测试操作的租约时间，不假称实际等待了完整租期。持续负载检查每个用户的原资金批次、实际模型请求、唯一结算记录、预占、并发槽位和结算队列。

资金守恒读取 PostgreSQL 完整主体账本，不使用工作区快照的最近 200 条调用。首轮 1070 请求的持续负载本身通过，但末尾总余额断言错误使用了这个分页快照；该失败结果保留，修正检查口径后重新执行整轮，不能把它解释为产品余额不守恒。

结果见 [汇总](../validation/higress-stability-2026-10-29/summary.json)、[75 项完整检查](../validation/higress-stability-2026-10-29/result.json)、[路径改写回归](../validation/higress-stability-2026-10-29/route-rewrite-regression.json) 和 [验证口径修正前的失败](../validation/higress-stability-2026-10-29/previous-check-failure.json)。

完整重跑 75 项通过。持续负载实际持续 181.305 秒，1081 / 1081 请求成功，模型请求和唯一结算记录均为 1081；四个用户原批次合计扣减 142692 微元，与已确认费用逐笔相等。本轮负载遗留预占、活跃限流槽位和结算队列均为 0，P50 / P95 / 最大往返分别为 1230 / 2424 / 3925 毫秒。持续流实际 35.269 秒并返回最终用量。

独立导出的最终暂存源码通过三个后端包构建和 140 项控制面测试；保留其他未提交改动的当前工作区通过 175 项控制面测试、41 项代理测试和 5 项运行时探针测试。数字对应不同验证范围，不混算为同一套测试。

本轮真实模型请求为 0；此前 DeepSeek 验收预算仍为 10 次、配置价格估算上界 ¥0.078772。原默认工作区已恢复到 `http://localhost:5176/`；配置和资金保留证据见 [默认环境核对](../validation/higress-stability-2026-10-29/default-preservation.json)。本轮结果仅说明指定本地拓扑下的功能与恢复检查通过，不代表真实模型长期负载、生产吞吐或高可用验收。
