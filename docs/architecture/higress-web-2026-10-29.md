# Higress 三类用户的页面任务验收

2026-10-29 至 10-30，按新员工、运营/项目经理、应用负责人的顺序完成页面任务。34 项浏览器检查和 38 项 PostgreSQL 关闭审计通过；修复了页面数据刷新、弹窗键盘焦点及审批失败提示三类问题。

## 实测范围

真实 Higress、隔离 PostgreSQL schema、真实登录和业务 API，模型为内部网络中的确定性替身。个人及项目调用由页面“在线使用”发起；应用调用使用页面签发的 Key，通过本地验收脚本模拟外部客户端。这次没有启动真实 Pi/Octop，也没有新增 DeepSeek 请求，不代表生产、高可用或真实模型复测。之前的真实 Pi/DeepSeek 结论见 [独立报告](higress-pi-deepseek-2026-10-29.md)。

浏览器使用本次工作区源码，其中还包含其他未提交的 Agent/读取优化改动；完整源码哈希见 [source-snapshot.json](../validation/higress-web-2026-10-29/source-snapshot.json)。本次只提交下述修复与验收工具，其他改动留在工作区。独立暂存基线的类型检查与构建结果见 [staged-baseline.json](../validation/higress-web-2026-10-29/staged-baseline.json)。

## 三条实际路径

| 顺序 | 页面操作与核对 | 结果 |
| --- | --- | --- |
| 1 新员工 | 首次申请个人开通 ¥0.30；运营批准 ¥0.20 并执行；员工在线调用，查看记录、价格和余额；退出登录后刷新 | 一个个人批次，剩余 ¥0.199868；一条确认费用 ¥0.000132。个人在线身份已吊销，刷新仍需登录。 |
| 2 运营/项目经理 | 运营向项目发放 ¥0.50 并双击确认；成员申请 ¥0.20；经理尝试批准 ¥1.00，失败后重试；修正原批准为 ¥0.10，再双击执行；成员项目在线调用 | 项目总预算只发一次，剩余未分配 ¥0.40。两次失败均保留，修正保留原申请及原批准记录；只分配一个 ¥0.10 批次，调用后剩余 ¥0.099868。个人余额不变。 |
| 3 应用负责人 | 无个人权益的负责人申请应用额度，运营批准 ¥0.25；页面签发 Key；启用调用、停用拒绝、恢复调用；再次调用并刷新页面核对结果 | 三次成功调用合计 ¥0.000396，应用余额 ¥0.249604。停用请求返回 401，无调用记录、无预占、余额不变。负责人未获得个人权益。 |

三类成功调用共 5 次，每次 input/output/cached tokens 为 13/14/4，按配置单价 2/8/0.5 元每百万 token 结算 ¥0.000132；每个请求只有一条结算记录，预占均终结。新增用户批次 ¥0.55 = 剩余 ¥0.549340 + 已确认费用 ¥0.000660。项目预算另保留未分配 ¥0.40。以上是替身验收金额，真实模型新增费用为 0。

证据：[数据库与审批历史](../validation/higress-web-2026-10-29/database-audit.json)、[34 项浏览器结果](../validation/higress-web-2026-10-29/ui-checks.json)。

## 实际缺口与修复

- 应用、Key 和项目详情原先仅在配置 `revision` 改变时重读。正常调用只改变账务，点击全局刷新后仍显示旧余额和调用数。现改为跟随最新工作区数据重新读取。第三次应用调用专门在配置版本不变时验证，刷新后显示 3 次、¥0.000396 和 ¥0.249604；Key 详情一致。
- 原生弹窗在挂载后才保存/恢复焦点不足以覆盖真实浏览器行为：Escape 后焦点落到 `body`，Shift+Tab 也能离开弹窗。共享 `Modal` 改在布局阶段保存触发控件，卸载恢复，并循环可见可用控件的 Tab/Shift+Tab；已被内层浮层处理的事件保持其原语义。更新共享组件契约，没有新增页面样式。
- 项目来源不足的失败提示和审批历史原先直接展示英文错误。现显示可操作的中文提示，数据库原始审计原因保持原样。

五种外壳 `azure/sidebar/next/classic/beacon` 都完成桌面弹窗键盘与宽度检查；Beacon 补充 390px 手机页面、抽屉、日期浮层及焦点返回检查。`sidebar` 的实际主题为 `data-ui="next"` 配合侧栏布局，已按现有合同判断。日期浮层 Escape 仅关闭日历，外层表单保留。1440/390 截图与检查未发现页面级横向溢出或浏览器控制台错误。

## 复验方式与证据边界

日常入口仍为 `pnpm dev`，`http://localhost:5176/`。专门的隔离页面验收入口为 `pnpm check:higress:web`，需要可用 PostgreSQL、Podman 及既有固定镜像。它创建自己的 schema 和真实 Higress 内部替身网络，打印本轮目录与 URL；账号和口令仅存于该目录的 `session.json`，不读取真实上游凭据。

页面步骤按上表执行，金额和调用次数是关闭审计的固定预期；应用 Key 在页面用眼睛按钮查看后，存入本轮目录的 `app-key.txt`，随后依次运行 `node scripts/higress/web-fixture-call.mjs <本轮目录> active|disabled|restored|refresh`，停用/恢复由页面操作，不能连续运行四种状态。完成同等浏览器检查后，把包含 `success:true`、逐项 `{label,pass}` 的检查结果写入本轮 `finish.json`；关闭审计要求至少 34 项且全部通过，再核对账务、一次结算及替身请求轨迹。工具会移除自身容器、网络、schema 和私密临时目录，保留脱敏 JSON 结果。它是人工驱动的隔离工具，不是无人值守 UI 测试，也不是另一个日常启动器。

首轮工具漏配隔离 Web 的 `WEB_ORIGIN`，未发生页面业务写入；修正后重建隔离环境，见 [首轮观察](../validation/higress-web-2026-10-29/setup-observation.json)。一次脚本误把仍遮蔽的 Key 当成完整值，请求返回 401、未扣款；重新从页面主动查看后才开始四步应用 Key 验收。未把这些工具操作问题计入产品缺陷。

浏览器完成后运行器和 Podman VM 停止，最终审计从保留的 PostgreSQL 数据恢复；前后默认环境比较使用首轮页面写入前保存的原始基线。替身进程内存中的请求列表及匹配的网关逐请求访问行没有保留下来，因此这轮不宣称最终归档包含完整数据面逐请求轨迹。数据库账务、应用客户端响应、页面截图与键盘结果均已归档。之后恢复原 `pnpm dev`：Web 200、网关 `dataPlane=higress`，原工作区、业务配置、余额及真实额度文件指纹一致，见 [默认环境核对](../validation/higress-web-2026-10-29/default-restart.json)。最初启动存在短暂数据库连接失败，诊断连接及身份核对成功后原命令恢复，未删除状态或重建数据。

最后按 runtime 标签校验归属，清理两次尝试的私密目录、本轮隔离容器/网络/schema，见 [清理记录](../validation/higress-web-2026-10-29/cleanup.json)。默认环境保留运行。前端类型检查、最终构建和三个新增脚本语法检查通过；现有混合工作区 bundle 的大于 500KB 提示仍在，本次未扩展到打包优化。
