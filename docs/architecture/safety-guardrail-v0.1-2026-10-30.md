# 输入安全围栏 V0.1 实施与验收

2026-10-30，按[已认可方案](safety-guardrail-v0.1-plan-2026-10-30.md)完成规则型输入围栏。运营入口为“配置与排查 → 安全围栏”；原 `pnpm dev` / `http://localhost:5176/` 已恢复，新迁移已应用，原工作区配置、资金、状态文件及真实模型预算核对一致。默认策略保持关闭，由运营预览并确认后启用。

## 已实现范围

- 一份企业策略：关闭、仅记录、拦截；全部模型或指定逻辑模型。保存需要运营权限、原因、当前版本和签名影响预览，版本不匹配时拒绝保存。
- 自定义字面禁用词，以及疑似手机号、身份证号和 `sa_` / `sk-` 密钥格式规则。身份证校验日期和校验位；短密钥占位符不命中。自定义词 NFC 规范化、不区分大小写，最多 200 条、每条 2–128 字符、合计不超过 16KiB；运营不能上传任意正则。
- 在现有准入网关内检查输入，再由控制面在原准入事务中核对策略版本、记录事件并决定是否预占。检查个人、项目、应用的在线使用与直接 API；受控直连回退仍经过同一检查。
- 检查所有角色的历史消息、文本数组、工具参数、工具结果、描述与其它外发文本；解析工具参数中的 JSON 转义。只排除已验证的顶层模型控制标识；JSON 字段名同样扫描。扫描最多 32 层、50000 节点、2097152 字符，沿用请求体 1MiB 上限，越界不静默放行。
- 命中拦截返回 JSON HTTP 403，`error.type=safety_policy_violation`、`code=sensitive_input`，即使客户端请求流式也如此。调用详情显示被安全策略拦截、未转发、未预占、实际费用 0；仅记录模式继续按原用量与价格结算。
- 保存命中事件的请求、主体、用途、模型、策略版本、动作和规则编号；规则值、提示词、命中文本不进入事件、调用元数据或网关日记。事件一请求一条，重放不重复写入。元数据保留口径与现有调用记录一致，不纳入短期通知清理。
- 运营可查询、分页和按时间/主体/模型/请求号/类别/动作筛选事件；只有具备原调用查看权限的人可以看到该调用的安全结果。规则试测只在内存处理合成文本，不调用模型、不扣款、不保存正文或生成事件。首版只展示观察/拦截计数，不展示缺少统一分母的拦截率。

控制面内部凭据解析返回策略快照；外部请求中的同名字段不能覆盖服务端检测。缺少必须的检测结果、扫描失败等返回 503，版本过时返回 409，不分派模型；已明确未准入的扫描失败会清除授权日记，不遗留恢复队列。重放保留原拒绝/准入结果；策略改变不追溯改写原费用。

## 页面回归中发现的问题

开发模式 StrictMode 可能发起重复初始化。原初始化没有失效保护，迟到的初始化响应可能在用户进入安全围栏后再次选择运营首页。现在初始化 effect 取消后不再提交状态或导航；五套外壳重新验证通过。修复前失败见 [初始化前后证据](../validation/guardrail-2026-10-30/browser-before-bootstrap-fix.json)。

另有两类检查脚本问题：刚保存即点击仍在刷新的禁用按钮，以及程序点击未建立真实焦点却断言 Escape 返回按钮。已增加可用状态等待和点击前焦点设置，保留[首轮时序失败](../validation/guardrail-2026-10-30/browser-first-timing-failure.json)、[导航排查记录](../validation/guardrail-2026-10-30/browser-second-navigation-timing.json)、[焦点检查器观察](../validation/guardrail-2026-10-30/browser-harness-focus.json)。不把这些检查器问题计入产品围栏缺陷。

## 可重复验收与演示

```powershell
# 独立 API、真实 Higress、PostgreSQL、确定性模型验收
pnpm check:guardrail

# 同时运行独立 Chrome 页面回归，涵盖五种外壳及手机宽度
pnpm check:guardrail --browser
```

脚本只使用本地替身，不读取真实上游凭据；需要现有 PostgreSQL、Podman 固定镜像及 Chrome。创建自己的目录、schema、容器和网络；按归属清理，脱敏报告保存在 `.runtime/guardrail-results/`。浏览器使用自己的 headless Chrome profile，不访问日常浏览器。诊断时可设置 `GUARDRAIL_BROWSER_HOLD=true` 保留本轮入口，独立运行 `node scripts/check-guardrail-web.mjs <打印的本轮目录>` 完成页面回归；这仍是专用验证入口，日常只用 `pnpm dev`。

演示时使用本地模型和合成文本：先设置仅记录并试测，再切换拦截，从员工在线使用发起含合成号码的请求，查看明确拒绝、零费用及运营事件；换成正常任务再调用，最后关闭策略。关闭恢复及 API Key 的实际执行已在隔离环境验证，不应在默认工作区进行破坏性重置。

本轮新增厂商模型请求 **0 次**。原 DeepSeek 累计 22 次预算文件未修改；替身验收金额不代表厂商消费。输出审核、自动脱敏、语义级提示词攻击检测、图片附件、完整内容合规和生产安全认证不在 V0.1 范围。T11 模型目录与 T12 第二协议入口仍排队。
