# 模型计费倍率与运营报表首版方案

日期：2026-11-11。范围：本地实现与验证；不包含生产部署。

## 目标与兼容

- 模型定义增加计费倍率，默认 1，支持 0–100、最多六位小数；0 明确表示业务免费，上游仍可能产生成本。
- 保留服务映射现有输入、输出、缓存输入价格的含义，作为计费基准价。新计费价 = 基准价 × 模型倍率。上游成本价独立、显式配置；2026-11-17 起保存服务或调整计价时成本必填，Token 模型三项完整填写，其他计量模型填写单位成本，真实免费填 0。历史未知成本保持 null，下次保存时要求补齐；已有计费价格缺少采购依据，不能自动认定为成本。
- 相同模型的不同服务仍可以有不同计费价；首版不做统一售价、客户折扣、多级倍率、定时报送或供应商账单对账。
- 准入冻结基准价、倍率、计费价与成本价；报价、预占、结算、迟到用量和人工核对使用原快照。旧快照继续按原价格结算，不重算历史账。输出生成上限与预占估算继续分离。
- 金额按请求计算到微元，缓存输入是总输入的子集；倍率计算使用整数精度，不引入浮点累计误差。

## 运营入口

复用用量驾驶舱与排行榜，不新增平行统计系统。快捷时间：今天、昨天、近 7 天、近 30 天、本月至今、上月、自定义；统一 Asia/Shanghai，左闭右开，切换时间保留其他筛选。近 N 天包含今天及之前 N−1 个自然日；再次查询快捷范围时刷新截止时间，自定义日期保持用户填写的边界。单次查询保留 93 天上限。

增加项目、应用与服务来源筛选、服务来源聚合。总览和分组同时呈现已确认计费、已知估算成本、成本未知笔数，以及同一批已确认且成本已知调用的计费、成本与差额。不可用总计费减去不完整成本来冒充利润。

保留 CSV，增加 Excel（汇总、逐日、组织、项目、应用、人员、模型、服务来源各 Sheet）。文件注明时间范围、时区、生成时间、筛选和口径；各维度不能跨表相加。当前筛选内全部聚合结果导出，不把前端排行榜截断当全部结果。逐请求明细沿用调用日志查询，不在首版加入无界大文件导出。

## 成本与权限

- 成本是按配置价格和上游完整 usage 计算的估算，不是供应商确认账单；历史缺少成本快照的已转发调用记为成本未知。
- 已确认计费、待核对预占、未知用量分别统计；用量完整但计费待核对时仍可估算成本，差额只取计费已确认且成本已知的相同调用。
- 明确未转发的请求成本为 0；转发状态未知或用量不完整时不能推断成本为 0。
- 平台连接验证成本继续独立记录，不进入业务报表；首版不跨诊断记录合并成本。
- 成本、倍率与基准价仅运营可见；员工和项目经理仍只看到权限范围内的计费与用量。所有调用返回路径和聚合 API 在服务端去除敏感价格。

## 实现顺序与验收

1. 合同、配置校验、整数计价、准入快照与权限裁剪。
2. 内存与 PostgreSQL 聚合口径一致，增加成本完整度、筛选与来源维度。
3. 模型倍率与成本配置、快捷时间、运营报表与导出。
4. 验证默认倍率兼容、零倍率、缓存价格、调价在途/重放/核对、成本未知和真实零、权限隔离、SQL/内存一致及导出内容。
5. 构建与相关测试、隔离 PostgreSQL 验证、1440/390 截图、键盘与五套界面溢出检查。保留已有工作区数据，不进行付费上游调用。
