# 运营开通页面与开发清单 v0.10

这份清单约束“模型服务 → 模型池 → 个人 / 项目开通 → 员工可用”的第一条纵向流程。它服务于 UI 设计和后续 AI coding；页面中的身份、审批、验证和调用仍是本地模拟。

## 目标与边界

- 第一版只接入已经部署的模型服务，不在本流程中管理 GPU、模型部署或供应商采购。
- 模型目录、模型服务、模型池、个人开通方案、项目和额度是独立对象；页面要展示它们的关系，但不能把它们合并成一个“模型权限”字段。
- 模型池代表用途和权限范围，不代表独立算力；同一服务可以被多个池引用。
- 个人额度与项目额度分开，项目总额度先进入项目，再分配给成员；成员加入项目不自动获得余额。
- 申请项目时不选择模型池；运营审批时使用项目默认池预填，可改池或限制模型后再批准。
- 本地原型不接收真实密钥、不发送真实请求；模拟验证、审批、发放和调用均标记为演示。

## 页面与角色

| 页面 | 角色 | 必须完成的判断 |
| --- | --- | --- |
| 模型目录 | 运营 | 模型名称、对外标识、能力说明是否已定义；定义本身不代表已接入服务 |
| 模型服务 | 运营 | 服务地址、受控凭据引用、模型映射、验证状态和启停状态 |
| 模型池 | 运营 | 每个模型的来源服务、未加入 / 未开放 / 已开放状态、默认池和变更影响 |
| 个人开通方案 | 运营 | 方案关联的池、跟随或指定范围、金额、周期和有效期 |
| 成员 AI 使用权益 | 运营 | 将方案开通给人员；重复开通不重复发放 |
| 项目创建 / 审批 | 员工、运营 | 申请不选池；运营确认经理、池和范围；创建不自动产生预算 |
| 项目总额度与成员分配 | 运营、项目经理 | 总额进入项目批次；成员额度从具体批次分配并继承期限 |
| 员工首页 / 在线使用 | 员工、项目成员 | 按用途显示可用模型、适用余额和阻塞原因；不跨方案或跨项目借额 |

## 字段、默认值和交互规则

### 模型服务

- 服务名称：必填，保存后可编辑。
- 服务地址：必填，仅允许 HTTP(S)，不允许账号、密码、查询参数或片段。
- 访问凭据：只能选择受控凭据引用或无需凭据；不显示或保存明文密钥。
- 服务模型：从模型目录勾选，并填写每个模型的上游标识；同一服务内不能重复。
- 验证情景：原型提供通过、连接超时、鉴权失败、模型不存在四种模拟结果。修改地址、凭据或映射后，旧通过结果失效。
- 未验证、验证失败或已停用的服务不能把模型开放到模型池；可以先保存为“已加入 · 未开放”。
- 停用服务前展示关联池、权益和项目影响；停用后保留余额与历史日志，阻止对应来源的新调用。

### 模型池

- 按未归属的模型服务多选入池；同一模型允许多个服务来源共同承接流量。每个服务仅归属一个模型池，每个服务模型组合只纳入一次。
- 开放前检查来源服务已通过模拟验证且处于启用状态。
- 个人默认池和项目默认池只影响后续新建或审批预填，不迁移已有方案、项目或人员权益。
- 范围变更先预览关联方案、权益和项目的新增 / 关闭模型，再确认生效；资金不随模型范围转移。
- 跟随模型池会同步后续开放模型；仅指定模型不会因为池新增模型而扩大范围。

### 个人开通

- 个人方案默认取个人默认池，运营可改池；选择“跟随模型池”或“限制可用模型”。
- 员工申请个人开通时只填写事项、金额、场景和说明；运营审批时选择方案。
- 追加额度沿用既有权益，不重新选择模型池；开通与追加在申请事项中明确区分。
- 个人模型适用余额只计算“授权范围 + 有效批次”同时匹配的金额。

### 项目额度

- 项目申请页不出现模型池选择。
- 运营审批项目申请时默认预填项目默认池，可调整范围后批准。
- 创建项目成功后预算为零、成员余额为零；下一步由运营发放项目总额度。
- 添加成员只建立成员关系并继承项目模型范围，不自动发放额度。
- 分配必须选择项目来源批次、成员和金额；金额不能超过该批次待分配余额，成员余额继承批次有效期。
- 项目经理本人申请成员额度转运营审批；普通成员申请由项目经理审批。

## 状态契约

| 条件 | 页面文案 | 下一步 |
| --- | --- | --- |
| 没有个人有效授权 | 未开通模型 | 申请开通模型与额度 |
| 有授权但没有可用开放模型 | 模型暂不可用 | 查看模型范围；不引导追加额度 |
| 有模型权限但没有适用有效批次 | 无有效额度 | 申请对应来源额度 |
| 有适用批次但单次余额不足 | 额度不足 | 追加对应来源额度 |
| 模型、权限和单次额度均满足 | 可使用 | 在线使用或创建用途绑定凭证 |

## 验收清单

以下作为正式开发验收项，勾选框不代表生产实现已经完成。本地原型已完成的检查及限制见 [v0.10 评审记录](ui-review-operator-v0.10.md)。

- [ ] 新建模型定义后可回到服务表单，并保留父表单草稿。
- [ ] 四种模拟验证结果均显示原因；失败状态不允许开放模型。
- [ ] 服务修改会使旧验证结果失效；停用服务阻止新调用而保留历史。
- [ ] 模型池开放未验证来源时阻止保存；范围变更先预览再生效。
- [ ] 默认池只影响后续新建；既有个人权益和项目范围不迁移。
- [ ] 项目申请不选池，运营审批可改池；创建后预算和成员余额仍为零。
- [ ] 项目总额、添加成员、分配成员额度分别可见且顺序正确。
- [ ] 分配金额受批次待分配余额限制，且成员额度带来源批次和有效期。
- [ ] 员工页面能区分个人 / 项目用途，模型适用余额不借用其他方案或用途。
- [ ] 320、360、736、1024、1440px 无页面级横向溢出；键盘焦点可见。
- [ ] 浏览器检查仅访问本地文件，无真实凭据、审批、网关调用或生产写入。

## 开发提交要求

每个后续 AI coding 变更至少说明：继承的 design token 和组件、支持的角色 / 状态、模拟与真实边界、检查过的 viewport 和键盘路径、尚未验证的后端契约。任何偏离本清单的字段或状态先写入设计决策记录，再改页面。
