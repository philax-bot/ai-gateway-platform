DESIGN NOTES · NOT PRODUCT UI

设计说明与落地缺口

本文件是设计稿：只复用现有视觉语言与契约组件，不改业务规则。下面三块分别说明数据来源、状态覆盖，以及需要先补的契约与接口。

数据现状：哪些能算，哪些要新增

本页字段现有来源与状态
单条请求 / Token / 费用 / 结果已有 CallLog：requestId、inputTokens、outputTokens、actualAmount、outcome、completedAt
全量汇总（请求、费用、未知用量、待核对）已有 CallSummary，已含 activeUsers / pendingReview / unknownUsage
按人员 / 模型 / 组织的排名聚合需新接口 逐条 CallLog 可用 subjectId / modelId / organizationId 分组，但分页上限 50 条，控制面没有聚合端点
活跃人员分母（已开通人数）已有 entitlements 中 status=active 且未到期，去重 memberId
失败率分母已有口径 CallSummary.ended 与 forwarded；上游故障只用 forwarded 作分母
采集质量 / 最近采集时间已有 callDataQuality、MonitorSnapshot.collectedAt
  • 建议新增只读端点 POST /api/v1/platform/analytics/leaderboard：入参 {from,to,organizationId?,modelId?,purpose?,metric,limit}，返回 rows[] + summary + collectedAt + quality。
  • 权限跟随现有对象范围：普通员工只能看自己与本人职责内项目；运营看全企业。
  • 聚合在控制面侧完成（与 CallSummary 同源），不下发逐条日志到浏览器求和。

必须实现的状态

状态本页表现
尚无数据表格内空状态行：「本期还没有已结束调用」+ 查看全部历史；不用 0 填充 StatStrip。
采集失败页头 warning notice + 全部数字改为「未知」+ 检查采集链接；保留筛选条件。
样本不足少于 20 次请求的行标注「样本不足」，不参与百分比排名，名次显示「—」。
用量未知Token 列显示「未知 / 不完整」，该行不进入 Token 排名；金额若待核对则单列。
加载中保留页头与筛选，统计条与表格骨架屏；不整页 spinner。
无权限员工进入时隐藏人员排名，只显示本人用量与模型分布，并说明可见范围。

需要先补的契约（未补前不写进产品页面）

  • 提案 3.18 ShareBar（表格内占比条）：轨道 6px、圆角 999、填充 --action；aria-hidden，百分比单独成列，不靠长度读数；危险阈值用 --danger 变体。
  • 提案 4.5 驾驶舱页面配方：筛选条移到 StatStrip 之前并作用于全页（与 4.2 列表页顺序不同），hero 主数值只放汇总之外的唯一数字。
  • 提案 3.19 无图表原则：本版趋势用「行内条 + 日值」表达（复用 3.18），不引入折线/柱状图表组件；如确需时间序列图，先补图表契约（维度、空值、口径、a11y 表格替代）。

壳层（顶栏 / 左栏 / 页面标签 / 抽屉）完全继承 v4 + beacon 实现，本稿不新增壳层规则。

评审要定的问题

  • 可见范围：人员排名默认只给运营？经理看本部门、员工只看本人？（涉及隐私与管理语义）
  • 默认口径：默认按已确认费用还是请求数？排名窗口默认 7 天还是自然月？
  • 纳入范围：应用与项目调用是否单独成榜（本稿按主体分离，不混排）。
  • 排名用途：只做容量与成本排查，还是要联动额度管控（超阈值提醒/限流）？后者需要新规则，不在本页。
  • 导出：是否需要导出当前筛选的排名 CSV；导出属于新动作，需先确认权限与审计。
