# 供应商、模型池与个人模型工作台界面重做方案 v1

日期：2026-11-17。状态：**已实现（P0–P5），浏览器回归通过**。范围：`apps/web`。
依据：[组件选型与样式契约](ui-component-contract-v1.md)（下称“契约”）、[信标版审核界面](signal-atlas-v5-beacon-review.md)（设计目标）、[用户端导航与可用模型方案](user-model-discovery-v1.md)、[路由与多模态开源评估](../architecture/opensource-routing-providers-modalities-2026-11-12.md)。

本文只回答“这五个页面重做成什么样、拆成什么结构、复用/新增哪些共享件、怎么验证”。业务规则、准入、额度、结算、权限、路由算法一律不改；不新增第六套主题；参考仓库只取策略与组织方式，不复制实现。

---

## 1. 结论

现状的问题不是“颜色不好看”，而是**五个页面都停在“把开源后台翻译成表格/卡片”这一步**：运营侧把供应商、连接、凭据、容量压进同一张表；个人侧把模型铺成卡片墙，每张卡各挂一个主按钮；调用页把最关键的准入结论折进 `details` 里。重做的核心是三条：

1. **清单优先、详情后置**：供应商、模型池改成与项目/应用同一套「列表 → 对象页」（契约 4.6）；可用模型改成「清单 + 详情面板」。列表只放可比较字段，长文本一律进详情。
2. **一屏一个主动作**：去掉每张模型卡的 `使用此模型`、每个供应商行的两个按钮；页面唯一 primary 是当前任务（接入服务 / 在线使用 / 执行调用）。
3. **准入可视化**：把“能不能调、从哪个来源扣、预占多少、价格版本、差额与待核对”做成一张共享的**准入小票**，在线使用、多模态、模型详情三处共用。这是本产品区别于开源后台的地方，也是现在最缺的“设计感”。

页面重做清单：`providers` + 新对象页、`pools` + 新对象页、`available`、`online`、`multimodal`，以及成对的 `media-tasks`。

### 2.2 逐页要点

- **供应商**：`Providers.tsx` 全文只有一个表格面板 + 上游凭据面板 + “后续配置”导航面板。8 个内置模板与自定义供应商同权展示，无搜索、无筛选、无聚合，也没有供应商详情——要看某供应商的验证历史、协议能力、挂了多少服务，只能逐个点开编辑弹窗。凭据表 6 列全部是复合单元格（名称+供应商、版本+掩码、关联服务拼接、操作两枚链接）。底部“后续配置”三个按钮与左栏导航重复。
- **模型池**：`ModelPools.tsx` 一行要同时表达策略、故障隔离、默认池、来源数/模型数/可开放数以及每条来源的「模型·服务·权重/优先级·状态」。策略与隔离退化成 `cell-help` 小字，容量与健康完全没有呈现，试算入口在一个模态里，结果又一个模态。
- **可用模型**：卡片字段顺序固定为 厂商+状态 → 名称 → 标识+复制 → 说明 → 能力标签 → 两列参数 → 阻塞说明 → 两个按钮。三张卡的信息量完全相同，扫描时无法快速比较；厂商位显示“本地验收 · 已维护”这类对选型无帮助的文字；`可使用` 绿色标签重复三次。
- **在线使用**：单轮表单。用途与模型是两个裸 `<select>`，报价只在折叠里，回复是一段 `.reply`，没有本次用量与费用回执，也没有到调用记录的凭据（请求号只出现在多模态页）。
- **多模态工作台**：预估与执行两次点击，但预估结果只是一行 notice；“最近一次结果”用同一个面板兜住六种模态，视频还要跳走。

## 3. 设计原则（针对这五个页面）

1. **清单优先，详情后置**：列表只回答“有哪些、哪个能用、差在哪”；说明、协议细节、历史进对象页或详情面板。
2. **一个主动作**：页面级 primary 只有一个。行内只用 `.link-button` / `.ghost`；卡片不再各自携带主按钮。
3. **零值静默、状态只报异常**：默认启用不刷绿色胶囊，用中性文字；0 服务显示“未接入”而不是“0 个服务 / 0 个已验证”。
4. **身份统一**：供应商用既有 `ProviderMark`，模型用新增 `ModelMark`（类型标 + 单色底）+ 等宽 `modelId`。同一实体在任何页面外观一致。
5. **每笔费用都有一张准入小票**：允许/拒绝、来源、预占、价格版本、估算、回执（实际用量、差额、待核对）在同一块里，不再分散到 notice 与 details。
6. **未知优先于 0**：未采集、未验证、未试算、未定价各用各的文案；不把缺失写成 0 或“正常”。
7. **只扩契约不扩视觉**：新增结构进共享语义样式（参考 `analytics.css` / `workflow.css`），组件层不出现新的色值/圆角/字号，`model-discovery.css` 的卡片规则随卡片墙一起下线。

## 4. 需要先补进契约的共享件

按契约第 7 节“新组件准入”先登记，再实现。以下 6 个都只组合现有 token 与原子组件。

### 4.1 `ModelMark` + `ModelIdentity`（契约 3.21）

```text
┌ 对话 ┐  本地·通用助手
│ 文   │  test-model · 本地验收        [复制]
└──────┘
```

- `ModelMark`：28–32px 圆角方标，按 `ModelKind` 取固定浅底 + 深字（对话/图像/视频/向量/重排/识别/合成），相邻页一致；只做识别，不表达状态。
- `ModelIdentity`：标记 + 名称 + `modelId`（等宽）+ 厂商/来源副行 + 可选复制。列表行、详情头、小票、任务卡共用。
- 禁止：用状态色做标记底色；用 emoji 或 logo 图片代替。

### 4.2 `CapabilityMatrix`（契约 3.22）

供应商详情与模型池详情里表达“这个接入支持哪些类型、验证到哪一步”。

```text
          对话  图像  视频  向量  重排  识别  合成
OpenAI     ✓     ✓     ✓     ✓     –     ✓     ✓
Cohere     –     –     –     –     ✓     –     –
```

- 单元格三态：`已确认`（实心点 + ✓）、`未确认`（空心）、`不支持`（`–`），配色只用 `--ok` / `--muted` / `--line`。
- 列表页不铺矩阵，最多 3 个类型标签 + `+N`；矩阵只在详情。
- 窄屏降级为「类型行 + 三态文字」，不横向滚动。

### 4.3 `AdmissionTicket`（契约 3.23）

```text
┌ 本次准入 ─────────────────────────────┐
│ ● 可调用        ¥0.42 预占            │
│ 来源  个人·日常办公 / 2026-11 批次     │
│ 估算  输入 1,204 · 输出 512 Token      │
│ 价格  版本 v7 · 输入 ¥2 / 输出 ¥8      │
│ 完成后  输入 1,180 · 输出 498 · ¥0.39  │
│ 差额  −¥0.03 已释放                    │
└───────────────────────────────────────┘
```

- 四种状态：`可调用` / `不可调用（原因 + 修复动作）` / `结果未确认` / `已结算回执`。
- 拒绝时把修复动作做成 ticket 内的次级按钮（降低输出上限、查看额度、联系运营），不再另起 notice。
- 数值全部等宽；未知写“未知 / 未采集”。
- 只读展示，不放筛选；金额精度沿用业务口径。

### 4.4 `CapacityMeter`（契约 3.24）

- 复用 `ShareBar` 的三段：RPM / TPM / 并发，各显示 `当前 / 上限`，无上限时只写当前值不画百分比。
- 采集失败或过期显示“未知”，不用上一次读数；来源标注 `collectedAt`。

### 4.5 `ListDetail`（清单 + 详情面板，契约 3.25）

```text
┌ 清单 5/12 ────────────────┬ 详情 ────────────────────┐
│ ● 本地·通用助手  test-... │ 对话 · 本地验收           │
│   文 工具 流式            │ 说明 ……                   │
│ ○ 本地·分析助手  analy... │ 能力 [文本][图片理解]      │
│ …                        │ 上下文 131,072 · 输出 8,192│
│                          │ [在线使用]  接入方式        │
└──────────────────────────┴───────────────────────────┘
```

- 桌面两栏（清单 `minmax(0,1.35fr)` + 详情 `minmax(320px,1fr)`，详情 sticky）；≤900px 只留清单，详情走 `Modal` + `DetailGroup`。
- 清单是 `role="listbox"`（行 `role="option"`、`aria-selected`、roving tabindex），↑↓ 移动、Enter 进入详情、Tab 出清单。
- 详情区只有一个 `.primary`；清单行内不放按钮。
- 选中项在用途切换、刷新后保留；失效时选中相邻项并给一条 `notice`。

### 4.6 `MediaResult`（契约 3.26）

六种模态的结果读数器，外壳统一，内芯按类型：

| 类型 | 结果区 |
| --- | --- |
| 图像 | 缩略图网格（≤3 列）+ 单张下载/打开/失败占位 |
| 向量 | 条数 × 维度摘要 + 前 3 条数值预览 + 下载 JSON |
| 重排 | 按分数排序的列表：名次、分数条、原文索引、文本 |
| 识别 | 转写全文（可复制）+ 时长/用量 |
| 合成 | 音频播放器 + 下载 + 音色/格式回执 |
| 视频 | 任务卡（状态、进度、提交时间）→ 任务中心深链，本页不轮询 |

- 原始 JSON 仍保留在一个 disclosure 里，但不再是唯一出口。
- 结果保留提交时的模型与候选文档快照，不随下一次输入改写。

## 5. 逐页改造

### 5.1 供应商（`providers`，运营）

**新结构**

```text
页头：供应商 · 口径 ─────────────────────────── [接入模型服务]  ← 唯一 primary
StatStrip：供应商 8+2 · 已接通 3 · 服务连接 5（已验证 4） · 待处理 2
FilterBar（即时筛选）：搜索 · 接通状态 · 能力类型 · [模板 8 / 自定义 2] 分段
Table（按 已接通 / 未接入 / 已停用 分组）
  供应商                       能力        连接            最近验证        状态    操作
  ▣ OpenAI 兼容服务            对话+6      2 个 · 1 已验证  11-16 通过      启用    详情 ›
    兼容接口与自建推理服务      内置模板
  ▣ DeepSeek                   对话        未接入           —              启用    详情 ›
```

- **列定义**（行内不放说明长文）：供应商（标记 + 名称 + 一句说明 + 来源徽标）、能力（≤3 个类型 + `+N`）、连接（`N 个服务 · M 已验证`，0 显示“未接入”）、最近验证（`verifiedAt` + 结果，无则 `—`）、状态（**仅停用/待验证**用 `Status`，默认启用用中性文字）、操作（`详情 ›` 单一入口）。
- 顶部 primary 是「接入模型服务」（沿用 4.10 两步流与 `ProviderPicker`），「创建供应商」降为次级；「编辑配置 / 删除 / 恢复默认」进详情页。
- 移除底部“后续配置”面板（左栏已有入口）。
- 空态三分：无供应商（接入第一个）、筛选无结果（清除）、有供应商但全部未接入（说明下一步 + 接入服务）。
- 数据全部来自现快照（`d.services` 的 `verification` / `verifiedAt`），不加接口。

**供应商详情（对象页，`targetId` 深链）**

```text
← 返回供应商        ▣ OpenAI 兼容服务   [已启用]                [接入服务]
适配 openai · 服务 2 · 已验证 1 · 最近验证 11-16 14:02
▍连接（服务表：名称 / 映射模型数 / 协议 / 验证 / 最近调用 / 凭据版本 / 操作）
▍能力注册表（CapabilityMatrix：类型 × 三态 + 说明）
▍托管凭据（该供应商下：名称 / 当前版本 / 掩码 / 关联服务 / 轮换 / 版本使用记录）
▍接入说明（地址、适配协议、删除或恢复默认的入口与影响确认）
```

- 凭据从“与供应商并列的大表”降为详情里的一个分组；跨供应商总览保留一个「全部上游凭据」入口，放在页尾次级链接。
- 权限不变：`models.read` / `credentials.read`；写操作仍按 `models.write` / `credentials.write` 禁用并写原因。

### 5.2 模型池（`pools`，运营）

**列表**

```text
StatStrip：模型池 3 · 已开放模型 12 · 来源服务 8 · 待处理 2（未验证 / 未定价 / 未开放）
Table
  模型池                   策略 / 隔离            来源构成        开放模型     容量水位         默认   操作

  ▣ 多模态池               稳定 · 关闭            ▣▣ 2 服务      3 / 4 就绪    未知             项目   详情 ›
```

- 来源构成用小堆叠标记 + 计数，替代行内铺开每条来源。
- 容量列读 `/api/v1/platform/monitoring/capacity` 中 `kind:'pool'` 的行；未采集写“未知”，不写 0。
- 策略与故障隔离合成一列（`ROUTING_STRATEGIES` + `failureThreshold/cooldownSeconds`），不再是小字副行。
- 行操作只留 `详情 ›`；试算进详情。

**池详情（对象页）**

```text
← 返回模型池     通用对话池  [加权路由]                      [调整配置]
来源 3 · 开放模型 9/12 · 个人默认池 · 采集于 14:02
▍来源与候选（候选表：服务/模型 · 顺序(权重/优先级) · 健康(冷却/连续故障/最近失败) · 容量 · 状态 · 调整）
▍路由解释（选模型 → 候选排序 + 每个候选的通过/跳过原因 + 容量快照 + 采样时间）
   参数：模型 / 拟议策略 / 请求编号 / 预估输入输出 → [试算]（只读，不预占）
▍开放模型矩阵（模型 × 来源：✓开放 / 未就绪原因）
▍保护上限（池级 limits + 说明 + 语义化跳转“容量与保护”）
```

- 试算**内嵌页内**，直接复用 `/pools/:id/simulate` 与 `RoutingDecisionView` 的候选语义（`eligible / excluded / cooldown / capacity / quota_insufficient / selected`）。结果用结论条 + 候选表，与来源表同列对读。
- 页面固定三条口径文案：只读试算不预占、不调用上游、不改配置；候选跳过原因为准入时的真实判定；容量快照有时间戳。
- 不做拖拽排序：顺序语义由权重/优先级定义，拖拽会引入未定义行为。

- 卡片墙下线：`ModelCard`、`.model-card-grid`、`model-discovery.css` 中卡片段落一并移除（`PersonalHeader` 规则保留）。

```text
│ 用途/模型     │ 空态：三条示例任务          │ 可调用 ¥0.42  │
│ 余额/来源     │ 用户消息                    │ 来源/估算/价格 │
│ 输出上限      │ 回复（流式）                │ [发送]        │
│ 最近调用 →    │ composer                    │ 回执/请求号    │
└──────────────┴────────────────────────────┴──────────────┘
```

- 左栏是“会话设置”，用 `Field` 渲染用途/模型/输出上限（现在两处裸 `<select>` 收回组件体系）；余额与来源一行摘要，链到“我的额度”。
- 中栏：空态给三条示例任务（点击填入）；发送后消息流保留在本次会话内，流式追加；`Enter` 发送、`Shift+Enter` 换行、取消保留既有 abort 语义。
- 右栏 `AdmissionTicket`：发送前显示允许/拒绝与修复动作；发送后变回执（实际用量、费用、差额、待核对、请求号 → 调用记录）。
- 唯一 primary 是「发送」；「取消请求」为 ghost。
- 失败与未确认沿用现有文案，但落在小票状态上，不再插一条 notice。
- **行为边界**：多轮仅存在于本页会话内，不落库、不进调用记录合并；每一轮独立准入与计费。是否本轮做多轮见第 8 节 D2。

### 5.5 多模态工作台（`multimodal`，个人）

```text
页头：多模态工作台 · 口径                       [视频任务中心]
类型切换：图像 · 向量 · 重排 · 语音识别 · 语音合成 · 视频   ← .section-tabs
┌ 表单（5fr）──────────────┬ 结果与准入（7fr）──────────────┐
│ 类型专属字段（Field）      │ AdmissionTicket                │
│ 预估 → 执行               │ MediaResult（按类型读数器）      │
└─────────────────────────┴───────────────────────────────┘
```

- 六种模态改成页内分段，切换保留各自草稿（本页 state），不再用一个下拉 + 条件字段的混合表单。
- 三步固定：填参数 → 预估（小票，允许/拒绝 + 预估）→ 执行（唯一 primary）。执行中 `fieldset.form-fields[disabled]`。
- 结果区用 `MediaResult`：图像网格、向量摘要、重排排序表、识别全文、合成播放器、视频任务卡（跳任务中心）。原始 JSON 收进 disclosure。
- 最近一次结果固定在右栏，不随滚动丢失；`requestId` 常显。
- 未知结果态：`requestId` + “结果待确认” + 去调用记录核对 + “已核对，允许新请求”（沿用现有语义）。

### 5.6 视频任务中心（`media-tasks`，成对重做）

- 列表：任务 / 模型（`ModelIdentity`）· 状态（提交中/排队/生成中/已完成/失败/取消）· 用途/服务 · 费用状态 · 提交/结束 · 结果与操作。
- 失败原因直接显示（不进折叠）；`已完成` 给下载与预览，`生成中` 给进度与时间，`结果待确认` 给危险动作 + 二次确认。
- 自动刷新 5 秒、非活动页暂停，维持现状。

## 6. 兼容、口径与边界

- **五套壳层同构**：新结构走语义 token（如 `analytics.css`），不做“仅 beacon 可见”。理由：这是页面重做而非主题层，维护两套 DOM 会立刻分叉。信标版仍是设计目标，其它四套用同一结构、不同皮肤。
- **不改业务**：准入、额度、结算、权限、路由策略、命令与校验全部不动；复用 `/state`、`/quote`、`/online-credential`、`/pools/:id/simulate`、`/monitoring/capacity`、`/services/:id/verifications`、`/upstream-credentials/:id/usage`、`/media/tasks/query`。**本轮不新增后端接口与字段。**
- **不改口径**：未知不写 0；待核对金额不写 ¥0；余额不跨用途合并；配置就绪不等于已授权；试算不等准入。
- **不做**：模型对比矩阵、模型市场/未授权目录、拖拽排序、图表库、渐变 hero、头像徽章排行榜、自动探测能力。
- **风险**：`ListDetail` 是新的交互模式，需要键盘与窄屏细则；`AdmissionTicket` 在报价失败/刷新时可能出现“上一轮结论”，必须整块置为“待重新预估”，不能沿用旧结论。

## 9. 验收定义

1. 五个页面均无页面级横向溢出（320 / 360 / 736 / 1024 / 1440），表格只在容器内滚动。
2. 每页只有一个 `.primary`；行内只有链接/次级动作；禁用按钮写明原因。
3. 空、加载、错误、无权限、禁用、busy 六态齐备；空状态给下一步。
4. `ListDetail` 键盘：↑↓ 移动、Enter 进详情、Tab 出清单、Escape 回清单；窄屏详情为 `Modal` 且可回焦。
5. 小票四态（可调用/不可调用/未确认/已结算）在 1440 与 390 均可读，金额等宽对齐。
6. 未知值（未采集、未验证、未试算、未定价）不显示为 0；待核对金额不显示为 ¥0。
7. 五套壳层无回归；`pnpm check:web` 全通过；契约第 3、4 节与截图同步更新。
8. 不改后端命令、校验与数据口径；无权限路径与现状一致。

本地验证不代表生产部署或真实上游验收。
