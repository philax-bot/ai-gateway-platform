# 企业内部 AI 资源运营平台：首版易用性概设

版本：v1.1，整体评审稿  
日期：2026-10-14  
当前设计主文档，替代 v1.0 的首版范围与导航建议。

> 2026-10-15 更新：项目创建与审批、项目额度有效期、模型目录 / 服务 / 模型池和限流入口已按原型反馈修订，见 [v1.2 修订](token-operations-product-concept-v1.2.md)。上述主题冲突处以 v1.2 为准，其余范围延续本文。

## 1. 本次调整的结论

第一版优先完成核心业务，并让运营人员和员工通过清楚的引导成功使用。v1.0 把多租户运营、复杂窗口、规则引擎、共享容量配置和多种管理入口同时放入首版，超出了当前所需的配置复杂度。

本次不仅减少菜单，也减少需要用户先创建的对象、必填配置、可组合规则和操作步骤。

保留核心：接入已有模型、开通人员、一次性与周期额度、项目分配审批、独立应用额度、基础限流、可信计量与追溯。

后置扩展：复杂订阅窗口、多租户运营界面、自定义角色和开通规则引擎、高级路由、独立告警处置中心、外部审批编排及后付费结算。

不削弱的底线：身份与数据范围、额度一致性、共享容量保护、凭证安全、异常解释。它们不必都对应单独菜单。

## 2. 不变的业务边界

- 面向有自建算力与已部署模型的中大型企业，由一个部门集中运营。
- 只接入已有服务，不管理 GPU、模型部署或推理引擎。
- 两类主要使用者：运营人员和 AI 使用者。项目经理、应用负责人是附加职责。
- 项目、应用独立存在。应用不必挂项目，员工也不必先建项目或应用。
- 同一人可同时有通用套餐和项目额度；按用途分别使用。
- 应用总额度由运营人员设置，后付费及跨公司结算留作后续方向。
- 技术底座不预先限定；研究参考仍为 [原平台功能调研](../../research/ai-gateway-platform-research.md)，不是旧测试问题清单。

## 3. 首版导航

### 3.1 运营端：七个直接入口

```text
首页
模型
成员
额度套餐
项目
应用
用量
```

企业设置、通知与帮助放在顶部。设置是低频入口，仍属于首版配置范围，不通过藏进设置保留一整套复杂后台。

| 入口 | 打开后看到什么 | 最常用的操作 |
| --- | --- | --- |
| 首页 | 待办、开通进度、用量摘要、异常提醒 | 接入模型、开通成员、处理申请 |
| 模型 | 已接入模型列表、能力与可用状态 | 接入、编辑、验证、停止开放 |
| 成员 | 人员列表和简单组织筛选 | 邀请/导入、批量开通、发额度、停用 |
| 额度套餐 | 一次性和周期套餐、正在使用的人 | 新建套餐、发放、停止未来发放 |
| 项目 | 项目列表与项目详情 | 配置预算、管理成员、分配额度、审批 |
| 应用 | 应用列表与应用详情 | 设置负责人、模型、总额度和凭证 |
| 用量 | 用量概览与调用明细 | 看消耗、定位失败、追溯来源 |

七个入口均直接进入业务页面，不再套“模型服务 → 服务接入 → 接入对象”等导航层。详情仅显示当前任务需要的信息，尽量采用“概览与设置、使用记录”等少量分区。

### 3.2 使用端：四个基础入口

```text
使用 AI
我的额度
接入与密钥
使用记录
```

“我的项目”“我的应用”按权限出现。通知、帮助和账号信息在顶部。

- 使用 AI：默认首页。就绪时直接对话，未就绪时显示一个当前需要完成的动作；模型选择在页面内完成。
- 我的额度：来源、剩余和恢复时间；申请追加、申请进度都在这里，无独立“我的申请”菜单。
- 接入与密钥：个人 Key 生命周期、编程工具配置示例；帮助就近提供，不要求先读完整 API 手册。
- 使用记录：个人消耗与请求明细，展示失败原因及下一步。

基础在线文本对话保留；无需做完整工作流、知识库或文件处理平台。可以复用已有工具，但接入必须保留可信身份和个人额度控制。

## 5. 实际减少的规则复杂度

### 5.1 套餐先保留两类

首版支持一次性额度和按月发放。周期套餐默认不结转，余额、当期有效期和下次发放时间清楚可见。

5 小时＋自然周等多窗口订阅仍是后续产品方向，本次从首版实现范围中移出。任意周期、滚动窗口、结转上限和叠加倍率不作为首版配置项。

套餐最小业务内容为名称、一次性/每月、额度、可用模型范围及必要有效期。这里只界定配置量，不展开表单或接口详设。

选择套餐给成员开通时，一次操作完成其对应的模型使用授权和额度发放，不需要运营人员分别跳到授权菜单、限流菜单和账户菜单。内部仍分别记录授权与额度，能够解释失败与生效状态。

套餐到期或停止发放的影响清楚展示，不把停止未来发放隐式变成回收所有现有权益。单次临时加额无需创建新套餐。

### 5.2 一个用途对应一个额度来源

通用套餐和项目额度继续共存。个人 Key 和在线会话选择“日常使用”或某个有权使用的项目；选定后记住，不要求每次请求重新选择。

日常用途内有多笔适用额度时，固定使用“符合当前模型范围且最早到期、足够准入的一笔”；不开放优先级规则编辑器。首版不拆分一笔请求跨多个来源扣减。

没有足够的单笔适用额度时明确提示，不能用合计余额误导。项目额度耗尽时不自动借用个人或其他项目额度。

这是简化后的默认行为，不限制一个人同时拥有多种权益；跨来源自动补充及复杂扣减策略后置。

### 5.3 固定职责与审批路径

首版使用运营管理员、项目经理、应用负责人、普通成员四类职责，可以叠加。运营管理员只能在其授权企业范围内操作，不因此自动获得对话正文读取权限。

项目成员额度申请由项目经理处理；经理本人申请、项目总预算和应用额度追加由运营管理员处理。通用额度申请也由运营管理员处理。

有权限的直接发放无需额外审批；需要申请的走一次业务审批。首版不提供自定义审批流程或 TT 双向编排，平台内流程可独立使用。

### 5.4 单一默认保护配置

提供一套产品默认请求保护，覆盖有限并发、单次输出和必要速率边界。具体数值由后续技术验证确定，不虚构已验证的模型容量。

普通开通默认继承，不要求选择限流档位、创建策略或绑定资源池。运营人员有特殊需要时，在企业设置或成员/应用/模型详情中覆盖限制。

同一已登记接入连接下的模型共用容量边界。不同地址是否共享算力无法自动可靠推断，需要在模型高级设置中关联；不因菜单精简而取消共同上限。

关键业务预留容量、自动抢占与高级队列后置；首版保留公平使用所需的主体与共享并发限制。

## 6. 四条重点引导流程

### 6.1 接入第一个模型：一处完成

首页“接入模型” → 填写已有服务连接、选择或填写模型 → 核对能力、内部计价与默认限制 → 验证并开放。

推荐行为：

- 已登记连接可以复用，同一个服务接入多个模型时不重复填写凭据。
- 支持自动发现时提供模型列表，不支持时允许手工录入。
- 默认使用上游模型名作为调用名，需要时再改。
- 默认一个模型一个有效来源，不要求建立路由、供应商或资源池对象。
- 必须明确内部计价或“免费”，未知价格不能自动当零。验证调用的用途及计量归属透明。
- 验证失败保留输入，说明具体连接或能力问题；“保存配置”与“实际验证成功”分别显示。

### 6.2 给一批员工开通：一个批量动作

成员页选择人员 → 点击“开通 AI” → 选择已有套餐，或现场创建一个一次性/每月套餐 → 确认对象与额度 → 查看逐人结果并通知。

示例明确显示“30 人 × 每人 100 元 = 本次 3,000 元”。套餐中已有模型范围，不再让运营人员重复选模型、配置限流和创建个人 Key。

如果对象已经有权益，提示本次是追加哪一份来源；重复提交不能重复发放。同一批次中的失败人员可以单独处理。

### 6.3 员工首次使用：只提示当前缺口

| 当前情况 | 主操作 | 用户不用做的事 |
| --- | --- | --- |
| 权限和额度可用，进行办公 | 开始对话 | 不必创建 API Key、项目或应用 |
| 权限和额度可用，进行编程 | 配置编程工具 | 不必自己理解上游连接和路由 |
| 无额度 | 申请额度 | 系统根据用途找到项目经理或运营管理员 |
| 无模型权限 | 申请开通 | 不把权限问题说成余额不足 |
| 申请处理中 | 查看进度 | 不必在多个审批菜单间寻找 |
| 服务异常 | 查看状态或选择允许的替代模型 | 不默认要求重新创建 Key |

不通过一连串介绍弹窗证明完成引导。用户完成一个必要动作后，主入口自然进入下一步；已经具备条件的人不重复跑教程。

### 6.4 项目与应用：各自在详情完成

- 项目：设置负责人和总预算 → 添加成员 → 分配额度；成员申请进入经理首页待办。项目模型范围在项目内配置，分配时完成相应使用授权，不另建开通方案。
- 应用：设置负责人、组织、可用模型和总额度 → 交付应用凭证 → 接入验证。全程不需要选择项目或借用个人余额。

## 7. 七个运营页面的精简职责

| 页面 | 默认展示 | 详情或就近操作 | 不提供的首版配置 |
| --- | --- | --- | --- |
| 首页 | 接入/开通引导、申请待办、用量摘要、服务异常 | 处理申请、跳到具体对象 | 可自定义驾驶舱与复杂事件工作流 |
| 模型 | 名称、能力、状态、接入来源 | 一处编辑连接、计价、开放状态；运行情况与少量高级限制 | 主备权重、复杂路由、GPU 管理 |
| 成员 | 人员、部门、开通状态、额度摘要 | 批量开通/加额，个人来源和凭证状态、停用及职责转交 | 任意规则编排、继承授权编辑器 |
| 额度套餐 | 名称、类型、额度、使用人数 | 创建、发放、查看对象、逐期记录、停止未来发放 | 多窗口订阅、结转策略、优惠叠加 |
| 项目 | 负责人、预算、成员、消耗 | 总预算申请、成员分配与审批、来源记录、结束回收 | 项目券、共享池抢额度、成本中心分摊 |
| 应用 | 负责人、归属组织、额度、接入状态 | 模型、总额度、应用凭证、用量及追加申请 | 后付费、跨公司结算、关联项目前置条件 |
| 用量 | 总量趋势和对象维度 | 调用明细、错误、计量与额度来源 | 拓扑大屏、独立缓存中心、复杂财务报表 |

成员、项目、应用详情中的额度记录使用同一来源，不能出现不同页面各自维护一份余额。统一用量页面负责汇总，不负责重新记账。

## 8. 企业设置的真实范围

只包含四组低频配置：

1. 企业信息与成员加入方式：基本信息、时区、基础组织归属；可选一个新成员默认套餐。默认关闭自动发放，启用时明确适用人员类别，不误发给所有外部人员。
2. 默认使用限制：查看默认保护，按实际环境调整。显示影响范围，不创建可自由组合的策略系统。
3. 登录与通知：首批客户必需的身份连接，站内通知为基础；更多目录同步、外部审批等连接后置。
4. 操作记录与保留设置：统一查询管理变更，设置必要的数据保留；不默认开放对话正文给管理员。

租户数据边界从实现开始保留，首版按一个企业工作区交付；不展示多租户创建、切换、租户间资源调配或跨租户管理。需要多租户共用部署时，作为下一阶段产品能力设计和验收，不能宣称当前已有完整多租户运营功能。

外部协作人员仍需责任人和有效期；负责人、个人停用、项目结束和应用交接的边界仍保留。设置精简不取消这些管理要求。

## 9. 精简后必须保留的一致性

1. 个人、项目、应用的使用身份和额度来源明确；应用不继承负责人的个人余额和权限。
2. 额度发放、项目分配、消费分别记录。项目预算与成员获配额度不重复相加。
3. 多把 Key 不能绕过人员或应用总限额；共享连接与已标记共享资源有共同容量约束。
4. 预占和消费可解释；普通额度耗尽停止新调用，已准入请求继续核对。流式中断和用量缺失不能自动按零处理。
5. 重复提交、周期执行和消费事件不能重复授予或扣减。价格变化不改写历史依据。
6. 配置保存、生效中、可使用和实际调用成功各有含义；用户看到真实当前状态。
7. 模型状态、额度和审批只有一个业务来源；不同入口只展示不同范围的同一记录。
8. 用量、元数据和正文可见性分别管理。凭据不进入列表、日志、通知或报表明文。
9. 成员停用、项目暂停与应用停用不能相互误伤；历史及在途占用仍能追溯。
10. 内网运行、备份恢复和必要故障诊断属于交付基本能力，不能因菜单减少而取消。

## 10. 首版范围与明确后置

| 保留在首版 | 明确后置 |
| --- | --- |
| 已部署模型接入，文本对话、流式及编程所需工具调用能力验证 | 多源权重、自动主备、跨模型路由、首发无需求的 Embedding/Rerank 等协议适配 |
| 基础成员管理、部门归属、固定职责、就近授权 | 自定义角色、复杂组织继承与开通规则引擎 |

| 独立项目、预算和成员分配、简单审批 | 项目券、复杂流程编排和跨公司结算 |
| 独立应用总额度与凭证 | 后付费、信用额度与跨公司成本分摊 |
| 默认速率/并发保护、主体及必要共享容量边界 | 独立限流中心、预留容量产品、优先级队列与资源池运营中心 |
| 基础在线对话、个人 Key 和编程接入指引 | 完整知识库、工作流、复杂文件处理、办公套件自研 |
| 用量概览、调用追溯、对象变更记录、站内待办 | 独立财务中心、告警工单系统、拓扑大屏与缓存专题中心 |
| 单企业工作区及内部数据范围、内网交付 | 多租户运营控制台和跨租户资源配置 |

后置不是隐藏空菜单。未实现能力不显示入口，不让用户遇到“敬请期待”占位。正式首版是否支持某种外部工具或模型协议，须通过实际适配验证。

## 11. 易用性验收

以下为待实现后的产品验收目标，不是当前已经测得的使用效果；不凭概设承诺固定分钟数。

| 场景 | 验收标准 |
| --- | --- |
| 首次接入模型 | 从首页一个入口进入，在一条向导内完成，不强制先建供应商、资源池、路由或授权方案 |
| 批量开通 | 在成员页选择人员与套餐即可完成授权和发额度，能看见逐人结果 |
| 第一次发额度 | 没有套餐时可就地创建，不要求跳到另一个菜单重新开始 |
| 普通办公 | 有权限额度后可以直接进入对话，不要求创建 Key |
| 编程接入 | 在同一页面获得个人 Key、地址、模型及对应工具示例，失败能找到请求编号 |
| 项目经理 | 只使用项目详情即可完成成员分配和申请处理，不需要获得整个运营后台权限 |
| 应用负责人 | 无需建立项目即可接入；应用额度和凭证在同一详情可查 |
| 追加与申请 | 管理者就近加额；用户只看到一个适当申请入口，审批人由上下文确定 |
| 查错 | 从失败记录能识别权限、额度、限流或上游问题，并给出适用的下一步 |
| 配置负担 | 常见任务无需打开高级设置，也无需创建策略模板或绑定多个对象 |
| 空与错误状态 | 初次无数据、无权限、加载失败和无可用额度分别给出明确引导 |
| 未完成操作 | 返回页面后可以继续已保留的配置，服务端未完成结果不被显示为成功 |

低保真原型评审应请运营和使用人员各自走一遍上述路径。若需要解释大量后台对象或在多个页面来回寻找，即使菜单数量达标也视为易用性未达标。

## 12. 版本关系与下一阶段

本稿是首版产品范围、导航和默认行为的当前建议版本。[v1.0 完整概设](token-operations-product-concept-v1.md) 作为能力规划参考，不能再按其中全部功能安排首版实现。

下一阶段优先验证四个低保真流程：接入模型、批量开通、项目分配、员工首次使用。页面字段与接口应服从这些路径，不反过来把底层对象全部暴露给用户。
