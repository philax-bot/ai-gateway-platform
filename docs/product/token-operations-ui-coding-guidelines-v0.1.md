# Token 运营平台 UI 与 AI Coding 约束 v0.1

日期：2026-10-16。状态：用户已体验并认可 v0.10；本轮将其作为交互基线，补充共享 tokens、可操作的组件样板和使用契约。用户认可的是本地原型效果，不等同于生产验收。

本文档约束后续 AI coding、页面原型和前端实现的视觉与交互方向。它不是业务需求文档，也不代表已有生产实现。业务规则以 [企业运营能力修订 v1.3](token-operations-product-concept-v1.3.md) 及其未冲突的 v1.2、v1.1 为准；本规范解决的是“如何呈现和实现”。

## 1. 当前基线

采用 **Signal Atlas** 作为平台基线：以 **Signal Console** 作为主气质，采用 **Field Atlas** 的资源路径表达作为辅助：

- Signal Console 负责平台感：深色控制台、清晰导航、运行状态、待办风险和关键指标。
- Field Atlas 负责理解成本：组织 → 项目 / 应用 → 成员用途 → 模型池 → 调用日志的关系要能被看懂。
- 视觉目标是成熟的企业 AI 网关运营台，允许有艺术成分，但不能牺牲扫描、判断和操作效率。
- 不把探索页面混用成拼贴风格；后续页面只允许继承本基线，除非先记录新的设计决策。

## 2. AI coding 的工作顺序

每次生成或修改页面前，AI 必须按以下顺序工作：

0. 先读 [组件选型与样式契约](ui-component-contract-v1.md)，按数据形态和选项数量选定组件；多选、人员选择、筛选、统计和弹窗不得临场发明。
1. 先确认页面对应的业务域、角色、入口和完成动作，再开始写 JSX / HTML / CSS。
2. 先复用现有布局、导航、按钮、表格、状态和反馈组件；只有现有组件无法表达需求时才新增。
3. 先处理正常、空、加载、错误、无权限、待审批和数据待核对状态，再补装饰性视觉。
4. 所有模拟数据必须标明演示边界；不能把空列表写成没有功能，把缺失费用写成 0，把页面成功写成真实调用成功。
5. 修改后至少检查桌面宽度、窄屏宽度、深色主题、键盘焦点和主要操作路径；未检查的状态不得宣称完成。

## 3. 视觉语言

### 3.1 色彩

使用“深色中性底 + 青绿色运行色 + 黄绿色行动色 + 琥珀风险色”的层级，不使用紫色渐变或大面积装饰光晕。

当前 token 以 [共享变量文件](prototypes/signal-atlas-tokens.css) 为准；[组件样板](prototypes/signal-atlas-ui-kit.html) 与 07 主原型共用。以下是常用变量：

```css
--bg: #0b1114;
--surface: #121b20;
--surface2: #18262b;
--line: #2a3d43;
--text: #edf6f2;
--muted: #8fa5a8;
--action: #b9f45d;
--run: #71e0da;
--warn: #ffc46b;
--danger: #ff806f;
```

颜色必须同时配合文字、图标或形状表达状态。状态不能只靠颜色区分；费用待核对、采集失败、无样本、样本不足和真实告警必须使用不同文案。

### 3.2 排版与形状

- 正常业务页标题 28px，窄屏 25px；区域标题 17px，子标题 15px；辅助说明 11–12px；正文 14px，控件 13px。样板封面的大标题只用于文档展示，不是业务页标题尺寸。
- 只使用 400、500、700 三档字重；数字和金额使用等宽数字或 `tabular-nums`。
- 面板圆角 12px；普通控件 7px；状态标签 5px。以已确认主原型的实际值为准，不逐页自定。
- 间距使用 4、8、12、16、20、24、32px；既有页面骨架允许保留已确认的紧凑尺寸，不为整齐而批量改变密度。
- 按钮最小高度 38px，内边距 9 × 16px；输入框内边距 10 × 12px，高度随字体和行高伸展，不锁死文字高度。触屏按钮最小高度 44px。
- 图标用于导航、状态和工具按钮；有明确含义的图标按钮必须提供可见 tooltip 或可访问名称。

## 4. 页面骨架

运营端默认骨架为：左侧分组导航 → 顶部工作区 / 用户 / 通知 → 页面标题与主动作 → 指标或上下文带 → 主内容区 → 页面级反馈。

主导航按职责分组，不按数据库表分组。当前首版入口保持：运营概览、模型与算力、人员与访问、开通与发放、项目、应用、密钥管理、审批中心、运行监控、调用日志。低频设置进入平台设置，不抢占首页空间。

首页只放能帮助用户决定下一步的指标：用量、待办、运行状态、资源概况和最近活动。不要为了“看起来像平台”增加无行动价值的图表。

涉及资源关系的页面，应在标题附近显示当前范围，并用路径或来源标签说明额度来自组织、项目、应用还是个人用途。不得把不同来源的余额合并成一个不可解释的数字。

## 5. 组件行为

- **主按钮**：每个页面最多一个最高优先级主动作，文案使用动词；危险动作不得伪装成主动作。
- **表格**：列顺序按判断顺序排列；状态用文字标签；操作列只放当前角色有权限执行的动作；窄屏在表格自身区域滚动。
- **表单**：按“必填且决定后续 → 常用 → 高级”排序；能就地创建并回填的资源不强迫用户离开当前流程。
- **审批**：必须显示申请人、用途、金额、期限、来源和下一步影响；批准、驳回、撤回等状态不能只通过颜色表达。
- **额度**：展示总额、已用、可用、来源、到期日和计量口径；不同用途的额度分开呈现。
- **模型开通**：遵循概设 v1.3 第 13 节。池选择旁展示“跟随模型池”或“仅指定模型”及当前可用模型；默认配置、实际授权、适用额度分别表达。池变更先展示关联影响；个人追加额度不出现重新选池的控件，项目成员继承项目范围。
- **密钥**：列表只显示脱敏值或标识；创建、吊销和轮换必须有原因、影响和结果反馈；不在页面、日志或示例中输出明文密钥。
- **运行监控**：区分实时数据、历史快照和演示数据；没有样本不能渲染成“健康”。
- **调用日志**：详情优先展示结果、模型、耗时、Token、缓存和计费状态；用量或费用缺失显示“待核对”，不能显示 0。

## 6. 状态与反馈

每个主要页面至少定义以下状态：正常、空状态、加载中、连接失败、无权限、待审批、操作失败和操作成功。空状态要给出下一步动作，但不暗示系统没有该能力。成功提示说明发生了什么以及下一步在哪里继续；失败提示说明能否重试和需要修正的字段。

对真实写入、真实调用、导出、凭据签发 / 吊销、审批、发布和删除，原型可以展示入口，但默认标记 `NOT_RUN`，不得用模拟成功替代真实验收。

## 7. 响应式与可访问性

- 桌面优先，但 320px、360px、736px、1024px 和 1440px 均不得出现页面级横向溢出。
- 沿用主原型断点：1100px 收紧侧栏、将主要业务双列折为单列；760px 改为顶部可换行导航，表单单列；主动作保留在标题区域。不要为新页面另定一套断点。
- 所有按钮、输入、标签页和弹窗支持键盘焦点；焦点轮廓不能被裁切。
- 文案、状态和图表必须有可读文本；不能把数据只放在颜色、悬浮或图形中。
- 深色主题下正文、辅助文字和状态标签都要保持清晰对比；不要用低对比度灰色制造“高级感”。

## 8. AI coding 输出要求

AI 提交页面或组件时，说明以下内容：

- 继承了哪些现有组件和 token；
- 页面支持哪些角色和状态；
- 哪些操作只是模拟，哪些真实能力尚未接入；
- 已检查的 viewport、主题、键盘路径和主要交互；
- 未验证的边界以及下一步需要的输入。

不得在没有上下文的情况下另起一套颜色、导航、按钮语义、状态命名或业务数据口径。若确实需要偏离，先在本文件追加“设计决策记录”，再改页面。

## 9. 第一阶段验收清单

- [ ] 运营概览和员工工作台共享同一套视觉 token 和状态语言。
- [ ] 员工首次使用 → 申请额度 → 审批 → 开通 → 在线使用 / 编程接入 → 调用日志形成闭环。
- [ ] 运营人员可以从概览进入待办，并回到原用途继续处理。
- [ ] 组织、项目、应用、模型池、额度和日志的来源关系可追溯。
- [ ] 空、失败、待核对和无权限状态都可被理解和恢复。
- [ ] 桌面、窄屏、深色、键盘焦点和主要表单路径完成检查。
- [ ] 未把模拟数据、页面状态或 HTTP 成功宣称为生产能力。

## 10. 下一步建议

本节原定的纵向 UI 流程已在 v0.10 本地原型中覆盖，并于 2026-10-16 获得用户体验认可：

**员工首次登录 → 查看当前用途 → 申请额度 → 统一审批 → 获批后继续使用 → 查看调用日志。**

模型服务、模型池、人工开通、项目发放与分配也已纳入本地原型。当前已将复用内容沉淀为第 13 节的组件样板；下一阶段在确定正式前端仓库与技术栈后，将这些组件落实为工程组件，并先实现同一条纵向流程。自动开通调度、完整应用和监控等范围仍以产品概设为准，不能由本地原型推断已实现。

## 11. 设计决策：吸收 Token Desk 的首页组织（2026-10-16）

用户确认采用 08 版的员工首页和运营首页组织，融入 [Signal Atlas 主原型](prototypes/token-design-07-employee-quota-loop.html)，版本为 v0.9。保留深色底、黄绿色主动作、青色状态及 v1.3 的业务边界；08 保留为独立对比快照。第 10 节的纵向闭环继续在主原型中细化，不另起平行业务版本。

### 11.1 信息层级与页面职责

| 页面 | 首屏必须明确 | 详情展开 |
| --- | --- | --- |
| 员工首页 | 当前用途、该用途余额、已开放模型、可执行的下一步；当前余额只突出一次 | 其他用途用紧凑列表；申请进度独立展示；不放完整资源路径和批次表 |
| 运营首页 | 待我审批、额度分配情况、常用开通入口；待办直达同一申请 | 最近处理、资源概况；未接入监控显示未知，不显示健康或零告警 |
| 申请 | 申请对象、事项、金额、场景、审批人和获批影响 | 员工无需选池；个人追加与开通明确区分 |
| 审批 | 原申请、批准金额、期限、实际授权来源和影响 | 用资源路径说明个人方案或项目批次如何到达申请人；项目总额度不会自动进入成员余额 |
| 在线使用 / 模拟凭证接入 | 扣费用途、模型、该模型适用余额和当前阻塞原因 | 展开适用批次、各自余额与期限；不得把用途总余额当作每个模型的可用余额 |
| 我的额度 / 项目分配 | 当前范围、来源关系、可用金额、期限 | 保留 Field Atlas 路径与批次追溯，不在首页重复铺陈 |

首页主动作随状态变化；已有额度且追加申请待审批时继续允许使用，申请状态不能覆盖实际可用状态。首页选择用途后，在线使用、编程接入与后续申请保留该用途。

### 11.2 额度与模型的状态契约

| 条件 | 显示 | 下一步 |
| --- | --- | --- |
| 没有有效个人授权 | 未开通模型；历史授权过期时说明已过期 | 申请开通模型与额度；已有申请则查看进度 |
| 有授权，但范围内没有已开放模型；或选中的模型已不可用 | 模型暂不可用；可确认停用原因时再显示具体原因，不猜测故障 | 查看模型范围与运营处理说明，不以追加金额作为解决办法 |
| 有可用模型，但没有有效且适用于该模型的批次 | 无有效额度 | 申请对应来源额度；其他方案资金不能替代 |
| 适用批次存在，但剩余额度无法支持本次调用 | 额度不足 | 追加对应来源额度；不跨用途补扣 |
| 模型与额度均满足使用条件 | 可使用 | 在线开始使用 / 接入编程工具 |

用途余额可以汇总当前用途尚在有效期内的资金；该模型适用余额只能累计有效授权下允许该模型的有效批次。若本地演示要求单批次覆盖 ¥0.02，应明确解释零散余额无法覆盖的原因，不能扩大为正式计费规则。模型失效后保留用户已选模型及输入并解释阻塞，不静默替换成其他模型。

### 11.3 复用与范围

使用同一套用途选择器、状态判定、模型余额、来源路径、审批影响和按钮样式。后续 AI coding 不得逐页重新定义状态语义。主原型本轮只覆盖额度与开通；完整产品菜单继续以概设 v1.3 为准，不能从 08 的局部菜单推断删除应用、模型服务、全量密钥或运行监控。

## 12. 运营开通闭环（v0.10）

沿用 v0.9 的颜色、表单、状态标签、双列详情和来源路径。运营“模型管理”分组使用模型目录、模型服务、模型池、容量与保护四个独立页面入口；员工保持按用途查看模型，不展示服务配置。

- 运营总览提供资源接入、模型池、开通使用三步引导；个人和项目是并列路径，不将创建项目设为个人使用前置条件。
- 模型池缺服务、服务缺模型定义时支持就地创建。子任务保存或取消后恢复父任务草稿；已保存子对象不会因取消父任务被删除。
- 模型服务分别呈现配置是否保存、验证结果、启停状态。连接超时、鉴权失败、模型不存在分别说明。修改连接或模型映射后原验证失效，不沿用旧通过状态。
- 模型池通过多选未归属其他池的模型服务纳入其当前提供的全部模型；每个服务仅归属一个池，同一个模型允许由多个服务提供，以分担请求并增加独立服务容量；共享容量和池总保护仍生效。模型开放状态单独调整，新增默认暂不开放。未通过验证或已停用来源不能新开放；已有来源停用会阻止相关新调用。变更范围或来源先预览，资金不随模型变化转移。
- 项目创建后提供发放总额度、添加成员、分配额度的下一步；成员加入不自动发钱，分配继承来源批次期限。发放先预览金额、项目、期限与影响。
- 本地原型仅选演示凭据引用，不收集真实密钥。模拟验证与真实服务健康分开标注；首版真实实现的运行限流、计价、可信鉴权与验证机制仍需另行实施。

字段、默认值和可验收条件见 [运营开通页面与开发清单](operator-onboarding-ui-checklist-v0.10.md)。

## 13. 组件样板与 AI Coding 契约（UI Kit v0.1）

工程实现的组件选型、anatomy、状态和反模式以 [组件选型与样式契约 v1](ui-component-contract-v1.md) 为准；本节保留早期 UI Kit 的业务契约。

[打开组件样板](prototypes/signal-atlas-ui-kit.html)。用户已确认的 07 原型继续为业务交互基线；样板用于集中查阅和实现复用，不建立第二套业务状态。演示交互只在内存中变化，刷新恢复，不读写主原型的会话数据。

### 13.1 复用入口

- [signal-atlas-tokens.css](prototypes/signal-atlas-tokens.css)：颜色、间距、字号、控件尺寸、圆角、边框和焦点变量。
- [signal-atlas.css](prototypes/signal-atlas.css)：从 v0.10 提取的公共布局与组件样式，07 和样板直接共用；引入顺序为 tokens → 公共样式 → 页面专属样式。
- [signal-atlas-ui-kit.html](prototypes/signal-atlas-ui-kit.html)：按钮、表单、12 种反馈状态、范围选择、额度批次、来源路径和影响预览。
- `signal-atlas-ui-kit.css` 只负责样板文档布局，不应复制到业务页面充当新主题。

目前是 HTML / CSS UI Kit，尚未建立 React / Vue Component Library；不预先绑定框架或 UI 库。正式实现采用 Ant Design 等库时，主题值映射到这些变量，业务组合组件仍遵循以下契约。

### 13.2 组件使用契约

下列英文名称是后续工程组件的建议名，当前原型仍用 HTML 与 CSS 类实现。

| 组件 | 必要内容与状态 | 使用约束 |
| --- | --- | --- |
| ActionButton | 文案、主次/危险级别、禁用原因、busy | 一个任务区域只有一个主动作；busy 防重复且保持宽度；危险操作先显示影响 |
| FormField | 可见 label、值、必填、帮助、错误、disabled | label 关联 input；错误关联 aria-describedby / aria-invalid；提交错误后聚焦需修正字段；保留草稿 |
| MultiSelect | 已选标签、搜索、复选行、计数、全选、清空 | 只能用于表单多值字段；禁止原生 multiple、横排选项墙和临时多选；选择后面板保持打开；Escape 只关面板 |
| StatusNotice | 状态名称、原因、下一步 | 不只用颜色；未知数据不记零；无模型与无额度分别说明；待审批不覆盖已有可用状态 |
| ModelRangeSelector | 池、跟随/指定、当前模型、开放状态 | 新增开放模型只扩展跟随模式；指定为空不能保存；关闭/停用影响两种模式；追加个人额度不出现此组件 |
| PurposeBalance | 用途、用途总余额、模型、模型适用余额 | 各金额明确标注口径；模型适用余额只算匹配授权和有效批次；不跨用途或方案补扣 |
| SourcePath | 来源节点、对象名称、关系说明 | 仅在审批/详情/额度页展开；个人与项目独立；不得把应用或项目作为个人必经节点 |
| QuotaBatchTable | 来源、总额、已用、余额、期限、适用性 | 文字说明是否适用；缺数据不假定为零；窄屏仅表格容器横向滚动，可键盘聚焦 |
| ImpactPreview | 当前值、拟变更、受影响对象、保留内容、取消/确认、结果 | 预览不修改生效配置；取消保留原值；确认后反馈；弹窗限制焦点在内部，Escape 取消，关闭后返回触发按钮 |

### 13.3 组合与验收

- 基础层用 tokens，组件层复用行为，页面层只组合上下文、主动作和业务内容；页面不得重写同一状态或额度口径。
- 表单、列表、审批沿用既有角色与字段契约。样板中的演示按钮、固定金额、固定人员和模拟等待不进入生产业务逻辑。
- 自定义组件需补齐正常、空、加载、错误、无权限及实际相关业务状态；不强行给每个叶子组件添加无意义的状态。
- 涉及授权范围或资金变更必须显示对象、范围、期限和生效影响；前端校验不替代服务端权限和金额校验。
- 验收检查 320 / 360 / 736 / 1024 / 1440px、固定深色、键盘焦点与主流程；组件变更需检查共用该样式的 07 主原型。

样板的本地验证与剩余边界见 [UI Kit 检查记录](ui-kit-review-v0.1.md)。

## 14. 设计决策记录：Signal Atlas 日光界面与三种布局（2026-10-20）

用户反馈经典界面“对用户不友好且呆板”，要求重新设计并可一键切换；后续追加“主菜单在左、上方平台切换、右侧页面标签页”的参考布局。现提供三种界面：**左栏 + 标签页（默认）**、**顶栏**、**经典**。经典界面完整保留，可在登录页或应用右上角一键切换，选择写入浏览器存储。`?ui=sidebar` / `?ui=next` / `?ui=classic` 可用于临时对比，不写入存储。

- **范围**：只改前端壳层、导航、共享组件视觉与交互；业务规则、权限、数据口径、页面状态语义和命令流程不变。经典壳层、主色和页面结构保留，共享组件（筛选、统计、多选、人员选择）按统一规范改进；三种布局共用同一 React 页面和业务 API。
- **方向**：日光工作台。深绿主动作、琥珀/陶红风险、瓷绿画布；数据使用等宽数字。默认布局是最上方平台切换条、左侧深绿主菜单、右侧已打开页面标签；顶栏布局保留双层顶部导航；“配置与排查 / 工具与协作”常驻可见；增加 `Ctrl/Cmd+K` 页面命令面板。
- **签名**：顶栏布局的页头刻度尺、页面来源行、首屏 hero 纵向测量线，对应“资源路径与计量”的产品语义；不堆叠与业务无关的装饰。
- **复用**：继续使用 `Panel`、`Table`、`Status`、`Modal`、`EditorDialog`、`Tabs` 和原页面组件。日光主题与顶栏布局在 `apps/web/src/design-v2.css`；左栏 + 标签页布局在 `apps/web/src/design-v3.css`，限定在 `html[data-layout="sidebar"]`。切换状态见 `ui-mode.ts`，顶部导航/平台条见 `v2.tsx`、`v3.tsx`。
- **组件统一**：人员选择改为紧凑行列表（全选/清空/计数）；多选改为标准下拉多选（已选标签 + 搜索 + 复选行 + 全选/清空），替代原生 multiple 和横排复选框网格；调用/核对筛选改为常用条件 + 更多筛选 + 底部动作行；调用指标、监控汇总和项目汇总改为分隔统计条；禁用主按钮中性化，滚动条收细。筛选、多选和人员选择等结构同时作用于三种布局，统计条在日光主题中统一；不改变业务字段和提交语义。组件选型与样式固化在 [组件选型与样式契约 v1](ui-component-contract-v1.md)。
- **验收**：已通过 Web 类型检查和生产构建；完成 1440px / 390px 三种布局截图、平台/空间切换、页面标签打开/关闭/固定、移动抽屉、命令面板键盘路径、人员选择、多选、筛选/统计组件和主要页面检查；经典界面在线使用页回归与改造前一致，仅新增切换入口和共享组件改进。未覆盖 Safari / Firefox / 真实读屏软件和全部生产数据状态。
- **边界**：三种布局是呈现与交互层，不新增业务能力；命令面板只导航，不执行命令；页面标签不保存各页筛选/草稿，本次会话内保留，刷新后从默认页重建；更深入的逐页内容重排留待用户评审后继续。

详见 [Signal Atlas 日光界面说明](signal-atlas-v2-signal-desk.md)。

### 2026-11-11 模型管理菜单职责

- 运营模型管理分组常驻四个独立页面：模型目录、模型服务、模型池、容量与保护。五套壳层与命令面板使用同一页面集合，个人空间不展示配置入口。
- 模型服务管理连接、映射、价格及验证记录，保留首次接入三步引导；模型目录承担模型定义编辑；模型池管理多服务关联、开放状态、默认池与变更预览。池内可查看并编辑来源服务，服务可进入所属池编辑。
- 容量与保护展示企业默认、服务、服务模型、池和共享容量组的配置来源及本级采用上限；编辑复用原对象表单与命令，不另建配置副本。企业设置保留默认保护摘要并跳转。
- 共享容量仍使用共同标识计数并继承企业默认，不新增共享容量组的独立上限或实测容量承诺。运行状态与告警留在运行监控，内容安全留在安全围栏。
