# 页面信息精简清单

2026 年 11 月 18 日 · 本地开发工作区 · 产品排查与改版建议

**建议第一批改运营工作台、在线使用、运行监控、用量驾驶舱、费用核对。** 这五页各有一个明确任务，但目前最醒目的内容分别指向了开通人员、会话配置、资源容量、成本对账和通用调用统计。调整顺序、删去同屏重复、按需展开明细，就能直接缩短操作路径。

## 逐项修改清单

**第一批**直接解决误读和高频任务被挤出首屏的问题。**第二批**减少每次查找、比较和操作的成本。**第三批**处理低频场景或局部文案。优先级来自本次页面走查；实际访问频率和转化率未纳入排序。

### 二、运营、对账与排障

| 编号 | 页面与优先级 | 当前问题 | 建议改法 |
| --- | --- | --- | --- |
| 04 | 运营工作台 · 第一批 | 走查时唯一待办是 9 笔费用核对。队列显示 9，开通人员的大卡又显示「9 项待处理」并配「为同事开通」，下方统计再列待核对数。采集未知时，大卡合计还会把未知项按 0 相加。 | 把数字与动作放回同一行，例如「9 笔费用待核对　去核对」。审批、未生效、核对分别直达相应队列或筛选。把「为同事开通」留作独立常用动作；首次配置受阻时再突出配置引导。采集失败时显示「费用数量待核验」和检查入口。 |
| 05 | 用量驾驶舱 · 第一批 | 筛选之后先渲染完整「计费与成本报表」。运营趋势靠后，活跃人数又出现在指标条和仪表盘，两个导出按钮与查询并排。 | 默认概览先放当前时间范围、已确认费用、请求量和趋势，下方给主要用量来源。活跃人数与活跃率合在一处。成本报表放同页「计费与成本」视图，沿用时间与权限；导出收成一个入口选格式。成本未知数、可比样本及差额仍随成本报表展示。 |
| 06 | 排行榜 / 项目用量 · 第二批 | 运营表默认 10 列，同时展示请求、Token、费用、占比、异常、待核对等；切换排序后，页尾还用一句话重报第一名。个人「项目用量」普通入口默认是人员维度。 | 表格突出排名、对象、所选指标和相应占比，异常与待核对有值时给入口。补充列可展开；完整字段保留在导出。去掉第一名复述。项目经理从「项目用量」进入时默认项目维度，保留按人员下钻和现有可见范围。 |
| 07 | 调用记录与详情 · 第二批 | 查一笔请求之前要经过时间、用途等筛选、汇总和错误率口径。桌面首条记录到第 889 像素。详情里身份、路由、计价、时序又同时展开。 | 常用条件放时间范围、请求编号、结果。默认行显示时间、模型、结果、费用与计费状态；运营保留主体，个人弱化本人身份。请求编号可复制且可精确查找。详情先给结论；正常调用按需看协议、价格快照与追踪，失败调用直接展开错误与关联请求。 |
| 08 | 费用核对 · 第一批 | 待核对队列沿用调用记录的已结束请求、确认费用、用量未知、错误率等模块；本地样本还醒目地显示「确认费用 ¥0.00」，处理人要从表格右侧找动作。 | 表头只突出「待核对笔数」「待核对预占金额」。首行直接给请求、主体、预占、待核对原因或证据状态及「核对」，窄屏把动作放在金额旁。详细 Token 与错误率留给调用详情。确认前继续并列原预占、实收、释放或补扣金额。 |
| 09 | 运行监控 · 第一批 | 页面依次铺实时容量、运行情况、异常、历史、访问链路等。服务越多，异常越靠下；容量、读数、链路各有自己的暂停与刷新。 | 默认显示采集状态、数据时间、待恢复告警和异常队列；容量达到阈值时在这里给出资源与跳转。把完整容量表、访问链路放到各自页签。每个视图显示当前数据源的刷新状态和控制。采集失败、延迟、零流量各有明确文案。 |
| 10 | 安全围栏 · 第二批 | 安全事件排在整块策略配置之后；查一条命中记录时，先读规则覆盖说明，再读事件计数口径。 | 顶部一行显示防护模式、模型范围和「调整策略」。默认看事件，先展示时间、模型、处理结果、类别；规则编号与策略版本进事件详情。策略关闭、采集失败等状态直接可见，试测与完整规则放入策略视图。 |

| 27 | 多模态工作台 · 第二批 | 切换到单一任务后，空结果区仍逐项介绍图像、向量、重排、识别、合成和视频，顶部也一直交代视频后台查询。无可用模型时字段帮助与警告重复。 | 空结果只说当前类型，例如图像「生成后在这里预览」；选择视频时才说明后台查询。无可用模型时合并成一条原因和切换入口。保留「先预估、再执行」，在执行按钮旁显示本次单位、预占与拒绝原因。 |
| 28 | 视频任务中心 · 第三批 | 顶部与空状态都能去发起任务。每个任务的模型、任务 ID、请求 ID、服务和时间同时占行，「查看调用记录」还要再找对应请求。 | 主表保留模型、状态 / 进度、费用状态及当前动作。完成项突出下载，失败项突出原因，取消待确认直接标明。次级详情放两种编号与服务；查看调用记录时带入已有请求编号。空列表保留一个发起入口。 |

| 30 | 我的额度 · 第二批 | 余额带与来源表逐批显示金额，来源表与模型表又分别解释一次「同一来源被多个模型共用」。单批上限与总余额容易被看作两笔钱。 | 首屏并列「用途总余额」「单次最高可用」，两者不同时就地说明单次从一个批次扣费。只有多来源时画构成带；批次表保留剩余、到期和追加操作。原始金额、批次 ID、覆盖模型按行展开；模型表通过切换查看。 |
| 31 | 密钥与接入列表 · 第二批 | 用户尚未选择密钥时已显示已选数量和批量操作；每行把创建、到期、最近使用叠在一格，表尾又混合接入地址、批量上限和结算说明。 | 表头保留全选，选中后再给批量停用或吊销。列表主看脱敏标识、用途、状态、到期，按角色保留所有者。创建与使用时间进详情，地址进接入指引，批量影响进确认框。 |
| 32 | 密钥详情 / 编程工具接入 · 第二批 | 协议已经有切换，但选中协议后仍默认铺出工具配置、完整 HTTP 地址与 PowerShell 示例，后面接权益、最近调用、管理历史。 | 默认先完成工具配置，展示协议、Base URL、模型标识与认证方式。直接 HTTP 请求、命令示例和排错按需展开。权益来源、调用和历史各自进入明细。签发后的一次性保存提示继续醒目，密钥保持遮罩。 |
| 33 | 通知 · 第三批 | 每条通知都是一张卡，标题、正文、时间、标已读、原事项入口各占空间；同类额度通知连续出现时难以定位需处理项。 | 默认按时间分组，用紧凑行显示未读、标题、时间与摘要；展开看完整正文。审批或告警行直接进入对应对象，额度通知保留来源。把已有的「标为已读」收进行内次操作。 |
