# 用户端导航与可用模型方案 v1

日期：2026-11-11。范围：用户空间；运营空间保持现有分组侧栏。以 Signal Atlas 信标版为视觉目标，并兼容现有五套主题。

## 目标与入口

让用户能找到当前用途可用的模型、理解主要差异，并带着选中的模型进入在线使用。

- 用户空间使用顶部导航：开始使用、可用模型、在线使用、在线 Agent、我的额度。
- 我的申请／申请与审批、密钥与接入、调用记录、项目、应用、项目用量进入“更多”；应用和项目用量沿用现有权限与可见性条件。
- 通知、账号、退出和界面切换保留。窄屏使用可键盘操作的菜单弹窗。
- 用户空间不显示重复的已打开页面标签栏；保留页面挂载、草稿、筛选和滚动位置。运营导航及其标签栏不变。

## 模型展示与使用闭环

- “可用模型”按当前个人／项目用途展示，与我的额度和在线使用共用用途状态；不跨用途合并余额。
- 使用状态以服务端 `purposes[].models` 为准；新增 `purposes[].catalogModels` 只读投影，补充当前授权且开放范围内来源暂不可用的模型。结合允许读取的模型定义，保留无额度／暂不可用状态与下一步；不开放未授权全量目录，不修改原运行模型和余额投影。
- 卡片展示名称、模型标识、厂商、能力说明、运营确认的平台接入能力、平台配置上下文、可选最大输出参考值和当前使用状态。
- 支持名称／标识／说明搜索、能力筛选、模型标识复制、详情查看。
- “使用此模型”同时携带当前用途与模型。页面已经打开时也更新模型，保留用户输入；切换用途仍按原规则选择该用途的模型。请求准入以实时服务端结果为准。
- 无模型、筛选无结果、加载、刷新失败、复制失败和模型失效分别反馈，不将未知资料写成 0 或“支持”。

## 运营资料与数据边界

复用现有模型目录的登记／编辑入口与 `save.definition`，不建立第二份模型登记数据。

| 字段 | 维护与展示 |
| --- | --- |
| 名称、模型标识、说明、上下文 | 复用现有字段；说明用于能力定位与典型任务 |
| 厂商 `vendor` | 可选短文本；空值显示未维护，不从名称推断 |
| 平台已确认能力 `capabilities` | 可选枚举集合：文本、图片理解、工具调用、流式输出；空集合表示未维护，不表示不支持；由运营核实当前接入后维护 |
| 最大输出参考 `maxOutputTokens` | 可选正整数，不超过配置上下文；明确为资料参考，不新增准入限制，不混用 `estimatedOutputTokens` |

新增字段兼容旧模型；历史编辑请求未提供字段时保留原值，显式空值可清除。资料保存在现有 workspace JSON 中，无须增加数据库表。服务端负责类型、长度、枚举和数值边界校验，沿用运营权限、预览和审计。

用户端不展示服务地址、物理模型、服务来源和运营配置价格。首版不做价格比较、排行榜、未授权模型广场、能力自动探测，也不修改计费、额度、模型路由与应用 Key 接入方式。

## 组件与实现

- 复用 `Panel`、`Field`、`MultiSelect`、`Modal`、`Status`、详情分组、筛选条和主题语义 token。
- 在组件契约登记个人顶部导航和模型卡片组合，新增样式仅用于这两个共享模式，不另建主题或页面专属视觉体系。
- 改动集中在用户壳层、模型资料契约与保存校验、运营模型编辑、新模型页面、在线使用的模型选择联动。
- 现有工作区包含其他功能的未提交改动；本次增量实现，保留原有改动，不重置或清理开发数据。

## 验收

1. 模型资料可由运营保存并在用户卡片同步；普通用户不能修改模型定义，也不能读取未授权模型或服务配置。
2. 顶部五项与“更多”入口可达，管理员切换空间恢复运营侧栏；五套主题均可使用。
3. 个人／项目用途严格隔离；无额度模型保留且有明确下一步；点击使用准确选中模型，保留在线草稿。
4. 资料缺失、非法输入、旧请求兼容、模型失效、空态和失败态有验证。
5. Web typecheck、build，必要后端／契约测试通过；1440／390 截图、键盘菜单与弹窗、无页面级横向溢出。

本地验收不等同于生产部署或真实模型能力验证。
