## 调度与一致性修复

- 告警采样时间可来自数据库。投递调度单独使用队列创建时间，数据库与控制面的时钟差不会把新消息错误推迟为未来任务。单元测试覆盖未来采样时间。
- 内存和 PostgreSQL 都先汇总资金批次候选，再排序与准入。健康采样限定候选服务、最近十分钟及最多 10000 条。冷启动延迟仅从当前模型候选计算，避免混入其他模型的延迟。
- 未知、无流量、样本不足或采集失败不作为恢复证据。静默继续记录事件与审计，暂停通知。

## 运行与部署条件

日常入口仍为 `pnpm dev`，地址 `http://localhost:5176/`。本次重启前后，已有 4 个模型定义、3 个模型服务、3 个模型池的 ID 集合完全一致，原 PostgreSQL 工作区及外部请求开关保留。Web、控制面、网关均返回 HTTP 200，控制面和网关为 `ok`，日常数据面为 Higress。

托管凭据使用 `PLATFORM_CREDENTIAL_ENCRYPTION_KEY`，值为 32 字节 Base64。日常入口生成并复用 `.runtime/upstream-credential-key`，Windows ACL 已验证为当前用户独占、禁止继承。生产部署与备份恢复必须保留原主密钥，数据库备份本身不包含该明文密钥。现有 `UPSTREAM_` 引用继续兼容。

平台库保存凭据密文。Higress 发布时会把认证值带入私有数据面配置，管理 API 和相关配置应按部署秘密管理。平台页面、操作审计、回执与调用记录不返回凭据明文。供应商立即撤销旧值时，平台无法保证旧版本仍可访问，轮换需遵循供应商的过渡策略。

Webhook 使用 `NOTIFICATION_` 环境变量引用，密钥至少 32 字节。接收端验证 `X-Gateway-Timestamp` 与原始请求体的 HMAC-SHA256，按 `X-Gateway-Event-Id` 幂等处理。后台按分钟评估、投递和退避重试，最多 8 次。传输为至少一次，配置变化或静默会抑制旧待发通知。

同步验收的费用上限约束配置成本下的请求规模预估，供应商实际返回用量独立记录。异步视频验收复用工作台的正常用途与持久化任务，不另建诊断生成队列。取消只有在服务明确配置了受控路径与方法后开放。

真实供应商流式、工具、音色、文件格式、取消语义、签名接收端以及生产容量仍需按部署配置联调。本轮没有执行外部付费生成或生产发布。
