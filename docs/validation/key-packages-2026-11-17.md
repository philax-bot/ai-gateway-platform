# 个人密钥多套餐范围验证

日期：2026-11-17。范围：本地实现与隔离 PostgreSQL，本地模型替身；未发布到生产，未调用真实上游。

## 行为

- 签发个人密钥可选择全部有效套餐或多选指定套餐。候选为密钥使用者已开通、未到期且未撤销的权益，展示套餐名、模型池、可用模型、余额和到期日。
- `ManagedKey.entitlementIds` 缺省表示全部有效权益，兼容历史密钥且跟随后续开通；非空列表表示只使用列出的权益身份。显式空值、空列表、他人权益、失效权益及项目/应用附带个人范围均拒绝签发。
- 模型发现、动态授权、每个候选批次、模型池路由和结算来源使用同一限制。多个套餐有相同公开模型名时也不能越界路由或借用额度。
- 指定权益到期、撤销或余额不足后拒绝新请求，不自动纳入新开通权益。已预占调用继续按冻结的原来源结算。
- 确认预览、密钥列表及接入指引显示范围，详情仅列范围内的有效来源。项目、应用和在线会话保留原用途行为。

## 验证

- 合同、控制面和 Web 构建通过；Web 类型检查通过。
- 控制面 51 个测试文件、332 项测试通过，其中新增 6 项套餐范围测试，覆盖同模型隔离、预占/结算来源、余额不足不兜底、模型发现、多个权益、动态兼容和非法输入。
- `node scripts/check-web.mjs --key-packages-only --postgres`：43 项浏览器断言通过。验证实际签发密钥、同名模型的 PostgreSQL 路由与结算、范围外余额保留、指定套餐耗尽、多选兜底、后续新增权益、直接 API 越权拒绝，以及五套界面、1440/390 布局和键盘路径。
- 没有未捕获浏览器异常或页面级横向溢出。测试的密钥与套餐位于 runner 创建并清理的隔离工作区；日常工作区的现有数据和密钥范围保留。
- 日常服务通过 `pnpm dev` 恢复现有 PostgreSQL 工作区，上游 opt-in 配置保留。
