# 模型计费倍率与运营报表本地验证

日期：2026-11-11。对应 [首版方案](../product/model-billing-reports-v1.md)。范围为本地开发和隔离 PostgreSQL，未执行生产部署或付费上游调用。

## 已实现

- 模型计费倍率默认 1，支持 0–100、六位小数；既有服务价格保留为计费基准价。上游成本独立配置，未配置保持未知。配置保存在已有工作区 JSON，快照保存在既有准入 JSON，不新增迁移或重算历史。
- 整数乘法先计算基准价与倍率，再按整个请求向上取整到微元。缓存输入是输入子集；预占保守使用输入/缓存较高单价。报价、实际预占、结算、重放与核对均沿用准入冻结的倍率与价格。
- 模型目录展示含倍率计费价，调用详情保留运营可读的基准价、倍率和成本价；模型倍率与服务价格确认页可核对变化。服务成本三项需完整填写或全部留空。
- 用量驾驶舱增加成本报表、来源维度以及项目/应用/服务筛选；常用时间为今天、昨天、近7天、近30天、本月至今、上月、自定义。全部按 Asia/Shanghai，单次不超过93天；快捷时间保留其他筛选，再次查询刷新截止时刻。窄屏折叠详细筛选，键盘可展开 DateField 并按 Escape 返回。
- 汇总、逐日、组织、项目、应用、人员、模型、来源共8个统计 Sheet，另有报表说明；保留 CSV。数字保持数值类型，成本未知留空并计数，公式形态名称以文本导出。不同统计维度不可跨表相加。
- 成本、倍率与计费基准只对运营开放。统一响应边界覆盖快照、列表、对象详情、报价和关联调用；员工/项目经理保留原范围内的用量与计费。平台诊断独立统计；新连接验证使用显式成本价，未配置成本不阻止验证，但成本未知。

## 人工查看

开发入口：[http://localhost:5176/](http://localhost:5176/)。

1. 运营 → 模型目录 → 编辑模型定义 → 计费倍率；保存前核对原/新倍率。
2. 运营 → 模型服务 → 编辑服务与价格 → 模型的「上游成本（运营报表）」；填写三项成本价。
3. 运营 → 用量驾驶舱 → 常用时间 / 时间与对象筛选 → 查询，查看「计费与成本报表」，切换维度或导出 Excel / CSV。

## 边界

- 原有模型与服务的价格没有被修改，倍率缺省为1；既有价格不自动认定为采购成本。真实成本报表需要运营显式维护成本价，历史未知不会被回填为0。
- 业务成本是配置价估算，非供应商确认账单；差额只比较同批已确认且成本已知调用，不是财务利润。诊断成本不混入业务报表。
- 导出是当前筛选的完整聚合，不包含无界逐请求导出、年度大范围查询或定时发送。
- ExcelJS 4.4.0 按导出操作动态加载；构建保留大块体积提示，Excel分块约939kB / gzip271kB。首次导出有加载过程，失败可重试或使用CSV。
- 未提交、推送或部署生产；保留工作区原有无关改动和开发数据。
