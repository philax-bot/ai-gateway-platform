# 同模型多服务容量聚合验证（2026-11-05）

用户澄清模型池用于聚合同一模型的多个模型服务。本次撤销此前的池内模型去重限制，保留服务只归属一个池及服务模型组合不可重复的校验。

## 实现

- 表单继续使用 Field multiple / MultiSelect；同模型服务可同时选中，各自管理开放状态。模型列表及权益范围按模型去重，池详情及影响预览按服务模型组合逐条显示。
- 以请求 ID 对服务进行稳定哈希排序，在可用、已开放且价格完整的来源中分配请求。内存与 PostgreSQL 两种存储均检查实际容量，服务满载时尝试其他来源。PostgreSQL 按统一顺序锁定全部候选限流范围，成功候选只预占和计数一次。
- 池、主体、用途与共享容量上限仍生效。实际路由及价格快照随准入冻结，幂等重放保持原路由与预占。
- 同价来源共享报价版本，可在同价服务间分流；固定报价不转入不同单价来源。旧报价需刷新。未新增上游转发后重试、自动熔断或流中切换。

## 验证结果

- 控制面 typecheck、Web typecheck/build 通过；控制面全部 36 文件、209 项测试通过。构建仍提示主 JS chunk 超过 500 kB。
- `pnpm --filter @ai-gateway/control-plane... build` 后 `node scripts/check-pool-routing.mjs`：14 项通过。独立 PostgreSQL schema、两个 store 实例同时发起 16 个请求，每服务并发上限 1，恰好放行 2 个并分别选中两条服务，14 个限流，预占只有两笔；跨实例重放不重复扣款，日志保留实际来源与计价。RPM、TPM 备用容量和池公共上限均有效。
- 同一脚本启动真实本地 HTTP 上游和 direct 网关，两条并发请求分别进入两个保持打开的上游；第三条返回 429；释放后两条均返回各自上游的成功内容。未请求外部模型，未修改默认开发工作区；测试 schema、服务和 journal 自动清理。此结果不代表生产吞吐或 Higress 多来源运行验收。
