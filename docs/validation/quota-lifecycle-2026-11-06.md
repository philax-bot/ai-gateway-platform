# 项目与应用额度 P0 验收（2026-11-06）

本次在已有未提交审批体验改动之上实现；不覆盖原工作，不发布、不启动日常开发环境。验证使用独立端口、独立 PostgreSQL schema、独立 Chrome profile 和本地模型替身。

## 已落地

- 项目创建/申请、额度模式应用创建/申请、记账转额度申请：初始额度必填、默认空、大于 0；创建/审批生效和首次授额事务一致、幂等。项目初始预算仍需分配给成员。
- 应用创建申请进入统一审批中心，展示模式、负责人、组织、金额、有效期与模型范围，禁止自批，保留实际生效回执。
- 指定日期/长期有效，项目默认指定日期、应用默认长期有效。每次追加独立成批，成员继承项目来源期限。长期有效通过共享常量编码，保持既有 timestamp 契约兼容。
- 运营回收未分配项目预算/应用可用余额；经理退回成员余额到原预算；独立延期及延期申请。延期不增加金额、不复活过期批次，项目来源与未关闭成员批次同步。
- 移出成员关闭额度、停用项目 Key；已预占请求按原批次结算，释放金额留在原批次待退回。退回由经理明确执行，来源过期/关闭则进入回收记录。重新加入不恢复旧余额。
- 负责人、状态、模型范围变更预览；应用交接默认选择吊销旧 Key，也可明确保留。记录配置前后快照及初始授额；待执行申请重新检查职责、状态及模式。
- 分开呈现消费、预占/待核对、可用、过期、回收、退回；历史负记账余额独立保留。

## 升级与边界

- 新增迁移 `017_quota_changes.sql`，仅增加 `returned_amount` 与资金守恒约束；不补发、不修改存量额度期限。迁移已在隔离 PostgreSQL 启动过程中执行，尚未对日常开发库或生产部署执行。
- 旧的零金额项目创建待办不会静默授额；审批人须填写有效批准额度/期限，或关闭后重新申请。
- 新创建命令要求 `initialAmount` 与有效期限；相关验证脚本已显式补充。持久化 review/demo 的创建命令先尝试重放旧请求结果，再为全新请求补充初始参数，避免重复创建或补发。
- 不新增跨用途转账、额度转记账、自动补额、过期额度复活；单次调用仍须由一个有效批次承担预占。
- 负责人交接时保留旧 Key 意味着持有旧明文的人仍可能使用，页面明确说明；选择吊销后需重新签发。
- 成员移出后的后续预占释放为“待退回”，由经理在原批次再次退回；不提前分配在途资金。
