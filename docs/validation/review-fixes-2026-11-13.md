# 全量检查问题修复验证

日期：2026-11-13。范围为上一轮全量检查确认的三处产品问题及阻碍回归的旧验收脚本。状态：本地实现与相关隔离验收通过；未提交、未部署，未调用真实付费模型。

## 修复结果

- **多来源费用预估**：预估、个人/项目用途状态和应用详情遍历同一批次的全部来源；昂贵来源无法支付时继续检查其他来源。回归用例覆盖余额 1 元、来源价格 10 元和 0.1 元，核对用途状态、应用状态、预估、真实准入和余额不足边界。
- **视频取消恢复**：先解析受控目标与凭据，再记录请求；发送前失败保持可重试。传输结果待确认及旧版未确认标记允许用户经原确认弹窗重新请求取消，已确认接收时阻止重复发送。`cancel_uncertain` 作为任务结果中的布尔字段持久化，不需要新迁移。真实本地 HTTP 用例覆盖凭据解析失败、连接中断、上游拒绝、旧标记恢复、确认后的去重与不再提交生成。
- **个人导航溢出**：`PersonalHeader` 与 CSS 共用现有 1180px 断点，1180px 及以下使用共享菜单弹窗，运营侧栏断点保持原行为。通用浏览器检查覆盖 320、360、736、901、920、960、1024、1180、1181、1440px，并检查 1024px 菜单的键盘路径；个人模型发现覆盖五套主题的 1440、1024、920、390px。

继续使用 `Panel`、`Table`、`Modal`、`.danger-button`、`.cell-help` 和现有主题 token，没有新增页面专属视觉组件。取消状态明确区分已确认接收与结果待确认，最终任务与费用状态仍由后台查询和结算确定。
